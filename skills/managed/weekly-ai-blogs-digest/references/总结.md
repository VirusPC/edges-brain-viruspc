# 总结

选文表完成后开始。全文来自 `feeds.json` 里入选链接的 `summary`。补录全文只从 `user-backfill.json` 读。不重新抓取，也不跳过这些数据去打开网页。

主 Agent 不把整份 JSON 读进上下文。每批 3 到 5 篇，子 Agent 只对自己的链接跑：

```bash
/tmp/weekly-ai-blogs-digest-py312/bin/python scripts/fetch_feeds.py \
  --pick /path/to/ai-news-data/issues/YYYY-MM-DD/feeds.json \
  --link 'https://例子/a' --link 'https://例子/b'
```

产出 `products/summaries.json`。`node` 是 `summaries`。`inputs` 引用 `products/selection.json`、`feeds.json`，补录存在时再引用它。`rules.path` 指向本文件。

`rows` 与选文的链接一一对应。每条有 `link`、`title`、`one_line`。文章和项目够写时还有 `sections`：解决什么问题、如何解决、效果怎样、洞察与启发、相关工作。每段一两句。没有新的洞察就去掉那一段。没有数字就写定性结果。订阅源偏短就只留 `one_line`，并写 `short: true`，表示订阅源里只有这些。一句话里用一处 `mark` 包住句中已有的词，不改写成新词。

精选文章另有 `category` 和 `company`。主类只能是模型、架构、产品、实践、开源、其他，按这个顺序。发文公司按 `site/src/lib/ai-news-category-filter.mjs` 的名单归并。模型条目不加这套主类，改用 `points`：上线、定位、成绩，最后一条是可用或实测。价格、速度、效果三行用 `model-releases.json` 里的数字和 `rank`；`rank` 不是正整数就不写名次，没有数字就写「暂无」。项目卡不加主类和公司。「GitHub Trending（weekly / all 前 5）」标题下面不要写概括前五名字的介绍句。

站点还在读 markdown 时，模型发布要点写成这张卡片。关键数字用一处 `<mark class="note-card-hl">` 包住原句里已有的数字。

```html
<aside class="info-card">
<p class="info-card-label"><span>发布要点</span></p>
<ul>
<li><strong>上线</strong> 哪一天、在哪发布。</li>
<li><strong>成绩</strong> 原文里的数字，用 <mark class="note-card-hl">一处数字</mark> 标出来。</li>
</ul>
<p class="info-card-note">来源：<a href="{{url}}">{{标题}}</a></p>
</aside>
```

入选清单变了，或某篇全文变了，才重写那几行，并重算引用它们的页面表。榜单名次变了不重写文章总结。
