Timers

让 Agent 能主动醒来：timer 自己不开 run，由 scheduler 到期后写成 inbox 里的事件。

第 3 课 · 约 10 分钟 · 主来源：William Hu · Building always-on agents

学完这一课，你能做到

看到一个提醒，能判断它是 follow-up 还是 schedule。你能按顺序说出 scheduler 的三步，也知道 timer 必须放在独立存储里、自己并不会开 run；选用 durable execution engine 时，到期后仍要先写入 inbox。

和 inbox 在一起，Agent 才能主动醒来

timers 和 event inbox 一起，让 always-on agent 能够主动行动，而不只是等人来叫。 原文 · Timers

两类 timer：follow-up 和 schedule

timer 一般分成两类。 原文 · Timers

follow-up

这是 Agent 给自己设下的期限，例如过一会儿去看有没有回音。它是一次性的。到期以后，应当被标成完成。 原文 · Timers

schedule

这是按已知节奏重复发生的任务，例如每天一份通讯。follow-up 和 schedule 可以采用相近的结构，但 schedule 还需要记录自己的重复规则。到期以后，应当把下次时间改到下一回。 原文 · Timers

放在独立存储里，自己不开 run

timer 住在自己的耐用存储里，通常是另一张数据库表，和 inbox 分开。inbox 只应存放已经能做的事件。还没到期的提醒，不该提前挤进 inbox。 原文 · Timers

timer 自己不会开一次 run。 真正去「开火」的，是 scheduler。 原文 · Timers

scheduler 每一轮的三步

scheduler 通常是一个后台服务。它按固定间隔查看这份存储，并把已经到期的项开火。每一轮按下面三步走。 原文 · Timers

  1. 找出已到期的 timer扫描存储，找到那些已经到时间的项。 原文 · Timers
  2. 按类别更新follow-up 应当被标成完成；schedule 应当把到期时间改到下一次。 原文 · Timers
  3. 写入 inbox 并叫醒 worker把对应事件加进 inbox，再叫醒 worker。之后的路，就和第 2 课一样：由唯一的 worker 取出并开 run。 原文 · Timers

自建服务，或 durable execution engine

至于 scheduler 本身，原文给了两种做法：你可以自建一个后台服务，也可以使用 durable execution engine。 原文 · Timers

无论选哪一种，到期之后的那一步都没有变：把事件写入 inbox，并叫醒 worker。不要把 durable execution engine 理解成可以绕过 inbox、直接去叫 Agent。那是课里需要标明的推断禁区——原文只把它写成实现 scheduler 的选项。 原文 · Timers

合上原文，60 秒这样讲

「timer 和 inbox 一起，让 Agent 能主动醒来。它分成 follow-up 和 schedule：前者是给自己设的一次性期限，到期后标成完成；后者按已知节奏重复，到期后把时间改到下一回。timer 放在独立的耐用存储里，因为 inbox 只放已经能做的事件。timer 自己不开 run。scheduler 按固定间隔扫描：找出到期的，按类别更新，再写入 inbox 并叫醒 worker。scheduler 可以自建，也可以用 durable execution engine，但到期后仍然要先进入 inbox。」
