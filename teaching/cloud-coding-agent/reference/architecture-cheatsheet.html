架构速查

coding-agent-template 一页纸。面试前扫一遍就够。

一句话

Next.js 应用接任务、写进 Postgres，用 after() 在后台开 Vercel Sandbox，把仓库拉进去，让现成的 Agent CLI 改代码，模型请求走 AI Gateway，最后推送到任务分支，用户再点一下开 PR。

技术栈（以 package.json 为准）

  • Next.js 16.0.10、React 19.2.1 L57–61
  • @vercel/sandbox ^0.0.21 package.json L42
  • AI SDK ai 5.0.51 package.json L45
  • Postgres（Neon）+ Drizzle L23–50
  • Octokit 调 GitHub package.json L24
  • 登录：arctic + jose（不是 README 说的 NextAuth）L46–51

密钥和安全，一屏看完

  • 平台级：SANDBOX_VERCEL_TOKEN / TEAM_ID / PROJECT_ID 用来开 Sandbox；JWE_SECRET 加密登录会话；ENCRYPTION_KEY 加密数据库里的令牌和密钥。README.md L190–199
  • 会话用 jose 的 JWE（A256GCM）加密 lib/jwe/encrypt.ts L1–15；数据库字段用 AES-256-CBC 加密 lib/crypto.ts L3–35。
  • 用户密钥优先，没有就用平台环境变量 lib/api-keys/user-keys.ts L15–67。
  • GitHub 令牌被直接写进克隆地址，所以 Sandbox 里的 Agent 也看得到它 lib/sandbox/config.ts L69–86。
  • 每日次数上限默认 5（任务 + 追问一起算）README.md L266 lib/utils/rate-limit.ts L20–43。

  • 对不上的地方：注释说 SDK“没有关机方法”，但锁定的 0.0.21 就有 stop()；README 说 Keep Alive 关了不能追问，追问接口其实会新开一台；vercel.json 给任务接口的函数时长上限是 300 秒 vercel.json L1–L8。

  • 成本：按 CPU 实际使用时间 + 内存 × 开机时长计费，后者闲着也算 → 空转不是免费的。

预制环境与隔离（第 3 课）

层放什么什么时候过时模板现在
① 基础镜像系统、系统包、语言版本、Agent CLI（Dockerfile → vercel vcr build → VCR → Sandbox.create({ image })）按周 / 月重建，补安全更新没有：只传 runtime: 'node22' creation.ts L81–L103
② setup 脚本克隆、装依赖、生成代码；可联网，密钥只在这里脚本、环境变量、secrets 改了每个任务都跑：克隆、装依赖、dnf 装 25 个 Chromium 库、装 CLI L165–L324 L513–L565
③ 快照 / 缓存setup 的结果（source: { type: 'snapshot' }；Drives 放共享缓存）lockfile 变了、代码走远了、30 天没用被删没有：SDK 0.0.21 只有 git / tarball 两种 source
④ 任务阶段Agent 改代码、测试、推送—令牌在克隆地址里，网络默认全开
  • Vercel 自定义镜像：只支持 linux/amd64；不运行 ENTRYPOINT / CMD，用 runCommand() 起进程；WORKDIR 生效。默认镜像 vercel/sandbox/universal（Ubuntu）。runtime 已弃用；旧 runtime 跑 Amazon Linux 2023（dnf）。Images
  • 持久 Sandbox：getOrCreate({ name, onCreate, onResume })，快照过期会重建并重跑 onCreate → setup 要能重复跑。Drives 2026-10-15 起 GA。SDK Reference
  • 两条规则：密钥只在 setup，绝不进镜像或快照；Agent 阶段收紧网络（networkPolicy 默认 allow-all）。
  • 对照：Codex（setup + maintenance 脚本、缓存最多 12 小时、secrets 只给 setup、Agent 默认断网）· Copilot（copilot-setup-steps.yml，secrets 全程是环境变量，靠防火墙）· Codespaces prebuild（跑到 updateContentCommand，拍容器快照）· Cursor（Dockerfile + 幂等 install，成功的 Build 拍磁盘）· E2B templates（连运行中的进程一起拍，约 80 毫秒载入）。
  • 不是 Docker：“each sandbox runs in its own Firecracker microVM with a dedicated kernel” Vercel 文档。容器共用宿主内核（namespaces + cgroups）；microVM 各有内核（KVM）；gVisor 在用户态拦系统调用。OCI 镜像 = 文件系统层 + 配置，Vercel 只用前者当根文件系统。

进度链路与任务状态（第 5 课）

一段做法毛病
Sandbox → 服务器服务器拉：SDK 对 /cmd/{id}/logs 开 NDJSON 长连接，写进 Writable。Claude、Cursor 分离运行，Copilot 不分离，三家边跑边解析；Codex、Gemini、opencode 跑完一次性读长连接活在函数里，函数没了就没人读；Sandbox 从不回调
服务器 → 数据库tasks.logs（JSON 数组列）由 TaskLogger 先 SELECT 再整列 UPDATE task-logger.ts；Agent 回复每段整段覆盖 task_messages.content，不 await并发丢日志；平方级写放大；回复可能停在旧版本（推断）
数据库 → 浏览器setInterval：/api/tasks/{id} 5 秒、/messages 3 秒、/api/tasks 5 秒（侧边栏，全部任务带全部日志）；没有 SWR / SSE / WebSocket全量拉取、结束后不停；延迟最多一个周期
  • 状态：pending（插入）→ processing（流程开头 / 追问）→ completed（推送成功）/ error（异常、推送失败、计时器）/ stopped（只有停止接口写）。写状态无条件，终态可被覆盖。
  • 进度是写死的里程碑：10、15、20、25、30、35、(37)、42、44、50、100；50→100 是 Agent 干活的全部时间。
  • 停止：PATCH {action:'stop'} → 状态 stopped → killSandbox 查本实例内存；查不到时兜底分支删掉别的任务的记录、不 stop、仍报成功 sandbox-registry.ts。后台流程在 Agent 开跑后不再检查，跑完会写回 completed route.ts（推断）。
  • 时长：after() 受路由最长时长约束（Next.js），vercel.json 只给 300 秒；README 却写可选 5 分钟到 5 小时 → 超过约 5 分钟的任务按推断会卡在 processing。
  • 为什么轮询（推断）：函数活不长、实例不共享内存、浏览器请求早已结束，数据库是唯一公共处。参考方案：只追加的事件表 + ?after=seq 增量拉 + 可选 SSE（Last-Event-ID）+ 用 sandboxId 停机 + 带条件的状态迁移。
  • 对照：Open SWE 用 LangGraph 事件流（SSE）；Cursor Cloud Agents API 每个 run 一条 SSE，可续传；Vercel durable harness 从持久会话日志推流；Codex Cloud 的传输方式未查到公开说明。

密钥与信任边界（第 6 课）

秘密怎么存怎么进 Sandbox留在哪、多久
GitHub OAuth 令牌（repo 范围）AES-256-CBC 存 users 或 accounts create-github.ts写进克隆地址 config.ts L69–L86；Copilot 另放 GH_TOKEN.git/config，机器活多久就留多久；令牌本身到注销或一年不用才失效；“断开 GitHub”不吊销
用户 API key加密存 keys 表，只写不读 api-keys GET临时写进服务器 process.env，再按第 4 课四种走法送进去 index.ts L56–L75命令行、配置文件；进程里可能串到别的任务（推断）
平台模型 key（AI_GATEWAY_API_KEY 等）Vercel 环境变量用户没存 key 时兜底 user-keys.ts L22–L31同上；任何用户可用终端接口读出（推断）
MCP secret / env加密存 connectors connectors.ts L63–L65；列表接口解密发回浏览器任务开始时解密 route.ts L536–L578，写进各家配置；client secret 直接当 Bearer 发配置文件
总钥匙：ENCRYPTION_KEY、JWE_SECRET、SANDBOX_VERCEL_TOKEN、OAuth client secretVercel 环境变量不进只在服务器；全站一把，没有版本号
  • 信任边界：浏览器 ↔ 服务器 ↔ 数据库互信；Sandbox 当作不可信，但秘密都送了进去，出站网络全开。
  • 并发串号（推断）：process.env 进程共用，Fluid compute 下两个任务交错恢复，前一个用户的 key 会留在进程里；原值 undefined 会被写成字符串 "undefined"。
  • 脱敏只管 tasks.logs；task_messages、终端返回、GET /api/connectors 都不过。用假数据实测：裸 key、JSON 写法、名字不含 KEY/TOKEN/SECRET/PASSWORD 的、值里带点号斜杠的，全部漏过 logging.ts L6–L74。
  • 认证：GitHub / Vercel OAuth；会话是一年有效的 JWE cookie，无服务器端吊销；注销是 GET。
  • 授权：[taskId]/ 下 31 个路由都查归属（4 个没排除软删除）。缝在创建任务的批量赋值：客户端能写 sandboxId，终端按它用平台令牌连机器（推断，需知道别人的编号）。
  • 限速：每天 5 条（任务 + 用户消息）。新任务算两次、删了退额度、非原子、maxDuration 由客户端定且无上限。
威胁推荐做法
提示词注入外泄 key凭据代理 + 出站白名单（Vercel firewall）
GitHub 令牌权限过大GitHub App 安装令牌：限仓库、限权限、一小时过期（GitHub 文档）
准备阶段的秘密留到 Agent 阶段按阶段给秘密，Agent 阶段默认断网（Codex cloud）
Agent 推危险改动只推专用分支、强制人工审查、仓库范围令牌（Copilot）
key 串号 / 字段篡改 / 总钥匙泄露每任务独立 env 对象；字段白名单；信封加密 + 密钥版本号 + AES-GCM

总流程（六课合一）：浏览器提交 → POST /api/tasks 限速、校验、写 pending、解密令牌和 key → after() 后台（受函数 300 秒限制）→ Sandbox.create（Firecracker microVM）→ 带令牌 git clone → 现装 Agent CLI、免确认运行 → commit、push 新分支 → 用户点按钮开 PR。每一步写数据库，浏览器每 5 秒轮询。
