# Benchmark 审稿与设计注意点

> 来源：peng cheng 与 Agent Memory 专家的讨论（2026-09-16）  
> 整理日期：2026-09-16  
> 用途：给**设计**评测集的人和**审稿**评测集的人共用一份注意力清单。讨论从 agent-memory / 长上下文评测出发，下面的判据对一般 NLP / agent 基准同样成立。  
> 这不是又一篇 LoCoMo 精读。个案深挖见同目录 [`2026-09-16-LoCoMo-paper-10-questions.md`](2026-09-16-LoCoMo-paper-10-questions.md)。

作者和审稿人看的是同一张表，但问法不同。作者要证明「我这套任务 + 指标真的量到了声称的能力」；审稿人要判断「这些数字能不能支撑论文的句子」。两边最先卡住的，通常不是谁的分数更高，而是：**构念对不对、数据能不能信、系统能不能被稳定分开、协议能不能被别人复现并公平对比。** 分数表是证据，不是贡献本身。

下面八条按审稿人实际花注意力的大致优先级写。前四条过不了，后面的伦理、多语、维护再漂亮也救不了。

## 1. 构念效度：声称测的，和实际任务 / 指标是不是一回事

审稿人第一问几乎总是：你们**声称**在测什么能力，**实际**让系统做什么、用什么分数代表成功？两件事对得上，才谈得上「测到了」；对不上，后面所有涨分都可能是别的能力在代考。

构念（construct）是那个没法直接看见的潜在能力，比如「长期记忆」「跨任务经验迁移」「在线写入后再使用」。任务和指标只是操作化。操作化一旦偷换，论文标题里的词就会比实验里的行为大一圈。

一个常见错位是把「长期记忆」做成**事后静态语料上的 QA**：对话或轨迹已经结束，整份历史被封成库，再截断或检索答题。这能量「长历史事实能不能被取回」，却量不到「边写边用」——系统在过程中产生记忆、立刻被下一轮消费。写入时间轴和消费时间轴一旦拆开，分数反映的就不再是在线记忆环。

LoCoMo 适合当这张错位图的插图，而不是反面教材。它的数据生成侧其实是在线的（生成式智能体边聊边写 observation / 摘要），官方 QA 却多半是对话结束后的静态库检索或截断阅读。所以它是一份有约束的超长对话考场，不是 Project Memory / online write→use 的证明。更细的拆解——题型、F1、写入被冻结、产生/消费时间轴——见 [`2026-09-16-LoCoMo-paper-10-questions.md`](2026-09-16-LoCoMo-paper-10-questions.md)，这里不重复那篇十问。

设计时把「想测的句子」和「系统实际被允许看见什么、何时看见、怎样算对」写成同一段；审稿时把这两段对着读。差得越远，构念效度越低。

## 2. 数据来源与标注质量

数字站不站得住，先看材料从哪来、谁标的、标得有多稳。

真实数据贵，但生态效度清楚：许可、来源时间、是否可再分发，都要写明白。合成数据不是原罪——月级、多会话、带结构的真实对话往往弄不到——但必须说明**为什么合成、合成管线钉住了什么、人在回路做了什么**。审稿人要看到的是「有约束的合成」，不是「生成器自己说自己像人」。

一份说得过去的合成（justified synthesis）大致长这样：先有结构先验（人设、事件图、时间线、任务图），再让交互发生；有独立于生成模型的校验或人工修订；标注协议公开，并报告一致性（IAA / 双标抽样 / 抽检错误类型）。编辑率可以当作成本信号，**不能**代替「像人」实验。生成、表演、再由同类模型当裁判打回生成剧本，是循环风险，要在 Limitations 里自己点破。

相反，未经验证的生成器是：prompt 一把出题、答案键未审计、没有人审、没有协议、也没有「这批题为什么难、难在哪」的说明。这种集上的分数，审稿人会默认不可信。

许可与可再分发单独成项。拿不到许可证的「真实」日志，别人复现不了，贡献就会缩成一次私有演示。

## 3. 难度与区分度

难度回答「这道题难不难」；区分度回答「这套题能不能稳定地把不同系统排开」。两者相关，但不是一回事。饱和的容易题没有区分度；全体地板的难题如果排序仍稳定，仍然可以有区分度。

### 需要有区分度吗？

**需要。** 一份基准若不能诚实、稳定地把系统分开，它就无法支撑「A 优于 B」「该方法有效」「该能力仍未解决」这类句子。区分度不是为了把分数表拉得好看，而是为了让比较有信息量。

「诚实、稳定地分开」至少意味着：

- **强 / 弱 / 空 / 随机** 等对照不该塌成一堆。空记忆、安慰剂检索、随机基线如果和「完整方法」分数缠在一起，涨分就解释不清。
- 排序要能**支持论文的声称**。你说自己解决了时间推理，子集上强弱系统却分不开，声称就不成立。
- 难度最好是**结构化的**：按题型、尺度、是否需要多跳 / 更新 / 拒答切开，而不是只报一个总分。子集上的分离，往往比总分更有诊断价值。

绝对分差本身不是目标。全体 95 分的饱和集、或说不清为什么全体贴地板的集，都是失败模式：前者区分度消失，后者可能是题坏了、键错了、指标在惩罚合法改写，而不是能力真的为零。早期难题可以绝对分很低——只要相对排序稳定、对照不塌、错误能被归因。LoCoMo 2024 年「远低于人类」的绝对鸿沟后来被模型进度吃掉，恰恰说明：**卖点如果只绑在当时的绝对分上，会过期；绑在题型诊断和相对分离上，更耐用。**

审稿人会问的不是「你们的 SOTA 是不是最高」，而是「换一个稍弱或稍强的系统，表还会不会讲同一个故事」。

## 4. 评测协议可复现与可归因

别人拿不到同一套 split、prompt、解码和指标实现，你的表就是一次不可复查的演示。固定这些东西，并开源数据、脚本与打分代码，是最低限度的可复现。temperature、top-p、是否单次推理、随机种子、检索 top-k，都要写死；「我们用了 LLM-as-judge」还要交代裁判模型、rubric 和与人类的一致率。

可归因比可复现再往前一步。端到端一个分数，把检索失败、读到了却没用上、以及模型自带的世界知识搅在一起。审稿人会要 oracle / 错误分解：检索对了阅读是否仍错？只给 gold 证据能到多少？空上下文或拒答题是不是在考参数记忆？LoCoMo 的单一 F1 把这些问题裹住了，所以它的表适合同协议内比较，不适合当「记忆能力」的绝对读数——这正是协议设计要提前拆开的地方。

开源不是把仓库链接丢进脚注。脚本要能在声明的依赖下跑出同一张表；打分实现要和论文公式一致。仓内 port 和官方 `evaluation.py` 一旦分叉，分数就不能互相引用。

## 5. 基线诚实与对比公平

对比必须在同一模型、同一 harness、同一解码与同一预算下进行。自己的方法若享受私有 prompt、额外工具、更长窗口或未公开的后处理，而基线没有，涨分就不算数。

该有的对照按构念来选，而不是按对自己有利来选：

- **空 / 无记忆**：没有写入、没有检索，只靠当前输入或参数知识。
- **安慰剂**：检索到无关或打乱的记忆，用来抓「只要多了几段文本就涨分」。
- **全上下文**：能装下就硬读；装不下要写明截断规则。今天很多「长」基准的全上下文已经是强基线，不报它等于回避最朴素的对手。
- **官方 RAG / 官方记忆模块**：如果论文在挑战某个公开基准的官方设定，就应复现那条官方臂，而不是只报自己的重实现。

「我们比论文 Table 2 高」但换了裁判、换了题子集、换了模型世代，不是公平对比。私有协议只给自己的方法用，是审稿里非常常见、也非常容易被拒绝的操作。

## 6. 泄漏与污染

训练语料、评测容器和答案键都可能把「会做这道题」泄漏进去。审稿人会问：测试题是否可能出现在预训练或 SFT 里？issue / 对话里是否已经写了解法？评测镜像的 `.git` 里是否躺着参考补丁？答案键是否被模型背过，还是真的在推理？

对抗题和拒答题尤其要核实「难」是不是真的。如果模型只是从未见过这种问法，或答案键本身把合法拒答标成错误，崩分就不证明校准能力。答案键未审计的合成 QA，污染和键错误会叠在一起：模型既可能靠背答案涨分，也可能因键错被冤枉。

滚动更新、按模型截止日期切时间窗、显式标记可能污染的题，都是加分项。做不到就诚实写风险，不要假装「公开数据集 = 干净」。

## 7. 贡献是否成立

过了前面几关，才轮到：这件事**值不值得新开一篇 / 新开一个基准**。新尺度、新现象、新的可归因诊断，都是贡献；把已有 QA 换皮、换个生成器、换个名字，不是。

贡献声明要和 Limitations 对称。量不到在线写入、人类基线不可审计、生成器效度没证完、某条臂从未被社区复现——这些应写在 Limitations，而不是只写在审稿人的脑内。一份诚实的 Limitations 往往比多报两个百分点更能保住贡献：它标明分数能支撑什么、不能支撑什么。

对 Edges 自己：选公开基准来证明 memory，先问构念是否匹配，再问分数能不能当证明。评测管道跑通，只说明管道在，不说明记忆有效。

## 8. 次一档但仍常问

这些很少单独决定接收，但缺了会被点名，补上也不贵。

- **伦理与脱敏**：对话、日志、仓库 issue 里的个人信息、未公开 IP、内部工单，公开仓不能原样入库。合成人设也要避免把真实第三方写进去。
- **多语与领域迁移**：只在英文闲聊或只在热门 Python 仓上成立的结论，不要写成 universal memory。能做跨语 / 跨域子集最好；做不到就缩小声称。
- **维护**：冻结的 test split 如何保持可比，滚动集如何标版本，坏题如何勘误。没有维护计划的「活基准」，一年后分数不可比。

## 和 Edges 评测词汇的对照

仓内已经把两件事拆开：[ADR 0008](https://github.com/VirusPC/edges/blob/main/docs/adr/0008-evaluation-smoke-is-not-benchmark-proof.md) 写的是 **Evaluation Smoke ≠ Benchmark Proof**。冒烟证明「写入→检索→作答→打分」这条链路能复现；公开基准证明需要构念匹配、对照齐全、协议可复现。本清单管的是后一类该怎么设计和审；前一类的分数不要回填成后一类的结论。

## 收束

审稿人最关心的顺序是：**构念 → 数据可信 → 区分度 → 可复现且公平的协议**。分数表是证据，不是贡献。
