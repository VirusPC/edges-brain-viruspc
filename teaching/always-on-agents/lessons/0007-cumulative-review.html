第 7 课 · 约 10 分钟 · 主来源：William Hu · Building always-on agents

学完这一课，你能做到

合上前面六课和原文，能用自己的话把整个循环讲一遍，并能在「中途杀到一条 webhook」「用户答复一次推迟的调用」「一条 follow-up 到期」这类情景里，指出该由哪个原语接手，memory 和 outbox 在其中做什么。

先凭记忆把循环画出来

请先不要翻回第 1 课，也不要打开循环速查。用几句话或一张草图，按顺序写出：一次 run 从哪里开始，怎样经过五个原语，怎样结束，用户的答复和到期的 timer 又怎样回来。写完再点「对照答案」。

提示：从「Agent 大半时间在睡」起笔，经过 event inbox、worker、memory、permissions、outbox，再画上两条回来的路。

always-on 只是用户体验。Agent 大半时间在睡。每次 run 都从 inbox 里的事件开始，无论它是用户消息、webhook，还是到期的 timer。唯一的 worker 拾起事件，在新的或已有的 session 里叫醒 Agent。Agent 先读 memory 作为基线，在 permissions 内行动，再把学到的写入 memory。结束时，它可能把一行推进 outbox，由 dispatcher 交给用户；也可能判断什么也不必送；也可能发出一次 deferred tool call。用户若答复，答复再作为事件回到 inbox。一次 run 也可以给自己设一个 timer，到期后同样先变成 inbox 里的事件。每次 run 都很短，循环可以一直转，这才让人觉得它一直在。 原文 · The cycle / How everything fits together

若要对照一页纸的压缩版，打开 循环速查；若要把三条情景也放在手边，可看 情景速查。

交错练习：三条情景

下面每条情景都混进了不止一个原语。先自己判断，再对照答案。原文没有写明的地方，答案里会标明，不会编造偏好。

情景 A　一次 run 做到一半，新的 webhook 到了

请指出：这条 webhook 应当先进入哪一个原语？同一份 inbox 能不能再起一个 worker 来抢跑？中途到来的事件有哪三种处理？这次若开新的 run，session 通常是续上还是新开？这一步里 memory 和 outbox 各做什么？

  • webhook 应当先由 handler 很快确认并写入 event inbox，而不是直接去叫 Agent。 原文 · Event inbox
  • 同一 inbox 不能再起一个在工作的 worker 来抢跑。 原文 · Event inbox
  • 中途到来的事件，原文并列了三种处理：推到下一次 run、并进当前这次，或打断重来。它没有推荐哪一种。 原文 · Event inbox
  • webhook 属于「其余事件」，通常新开一份 session；原文把「续上已有 session」明确写给接着先前工作的事件，例如用户答复。 原文 · Event inbox
  • 当前这次尚未结束的 run，仍按原计划读、写 memory，并在结束时才可能写入 outbox。新 webhook 在被某一次 run 拾起之前，还不会动 memory 或 outbox。不要把「尚未开始的那次工作」提前写进 outbox。

情景 B　用户答复了一次 deferred tool call

请指出：当时那次 run 是否还在空等？session 去了哪里？答复应当先进入哪一个原语？新的 run 会不会续上原来的 session？等待期间 worker 在做什么？这次请求当初可以怎样交给用户？

  • 当时那次 run 已经结束，并不是一直挂着空等。session 保存在调用做到一半的地方。 原文 · Permissions
  • 用户答复作为事件回到 event inbox，并开一次新的 run，接着那份已保存的 session。 原文 · Permissions
  • 等待期间，worker 仍可拾起 inbox 里别的事件，Agent 不会被堵住。 原文 · Permissions
  • 当初把请求交给用户时，可以经过 outbox，也可以直接显示在界面上；原文把两条都写成可以。 原文 · Outbox

情景 C　一条 follow-up 到期了

请指出：是 timer 自己开 run，还是另有角色？scheduler 到期后先做什么、再把事件送到哪里？worker 随后怎样？这次 run 会不会自动续上旧 session？若 Agent 在这次里学到了新的用户偏好，应当写到哪里？若它决定暂时不打扰用户，属于哪一种结束方式？

  • timer 自己不会开 run。scheduler 找出这条已到期的 follow-up，把它标成完成，再把事件写入 inbox 并叫醒 worker。 原文 · Timers
  • 随后仍由唯一的 worker 取出事件并开 run。 原文 · Event inbox
  • 这次 run 是否续上旧 session：原文只明确把「用户答复」这类接着先前工作的事件写成续上已有 session，其余通常新开。到期的 follow-up 没有被单独写成必须续上旧 session，这里不做额外推断。 原文 · Event inbox
  • 新学到的用户偏好属于 user notes，应当写入 memory；已在别的系统里的事项则只存指针。 原文 · Memory
  • 决定暂时不打扰用户，属于三种结束方式里的「这次什么也不必送」。 原文 · Outbox
