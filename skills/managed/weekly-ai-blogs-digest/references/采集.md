# 采集

这一节点只抓订阅并落盘。产物是期次目录根上的 `feeds.json`、`feeds.index.json`、`github-trending.json`。不选文，不写总结，不写关键词。关键词见 [关键词](关键词.md)，榜单和模型发布见 [榜单](榜单.md)。

`feeds.json` 是 feed 给出的正文，不截断，也不打开文章页去补。`thin` 表示这条不足 280 字或为空，原样保留。`feeds.index.json` 只有标题、日期、链接、来源、`thin` 和开头约 400 字。`github-trending.json` 从同一份 feeds 抽出 `github-trending-weekly-all`。名次以 Trending feed 的 XML 原始顺序为准，不用数组顺序。Python、TypeScript 的 weekly 源只留在 `feeds.json`。

订阅真源是 [`feeds/ai-coding-blogs.opml`](../feeds/ai-coding-blogs.opml) 和 [`feeds/ai-coding-blogs.meta.json`](../feeds/ai-coding-blogs.meta.json)。退路见 [订阅源兜底](../../../../.edges/routines/weekly-ai-blogs-digest/INDEX.md#订阅源兜底)。相信这份订阅。feed 里是简介，快照里就记简介。

`user-backfill.json` 不由这一节点生成，也不并进 feeds 或索引。

## 开始与完成

窗口日期已经写死就可以和榜单并行开始。完成时，窗口内条目在 `feeds.json`，索引和 weekly/all 摘录都在。抓完把自己的文件状态写进 `manifest.json`。

feeds 的条目或正文变了，重抽索引和相关 trending。weekly/all 的标题、正文或 XML 名次变了，才重写对应项目卡的下游。AA、Arena、OpenRouter 的输入没变就不再拉。

## 命令

Python 3.12。在本 skill 目录：

```bash
python3.12 -m venv /tmp/weekly-ai-blogs-digest-py312
/tmp/weekly-ai-blogs-digest-py312/bin/pip install -r scripts/requirements.txt -r scripts/requirements-leaderboard.txt
```

`scripts/requirements-leaderboard.txt` 固定 `pyarrow==17.0.0`。

```bash
PY=/tmp/weekly-ai-blogs-digest-py312/bin/python
$PY scripts/fetch_feeds.py \
  --since YYYY-MM-DD --until YYYY-MM-DD \
  --out /path/to/ai-news-data/issues/YYYY-MM-DD/feeds.json \
  --index-out /path/to/ai-news-data/issues/YYYY-MM-DD/feeds.index.json
```

然后把 `source` 为 `github-trending-weekly-all` 的条目写入 `github-trending.json`。
