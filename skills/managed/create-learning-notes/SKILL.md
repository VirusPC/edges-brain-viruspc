# create-learning-notes

一份学习笔记只有两部分，**事实和观点严格分开**：

- **Summary**：材料本身说了什么。忠于原文，不掺评价。
- **Comments**：读的人怎么想。启发、质疑、联系、要做的事。

## 模板

```markdown
# <材料标题>

- 来源：[<标题>](<URL>) · <作者> · <日期/会议>
- 类型：文章 | 论文 | 演讲 | 视频 | 书 | 代码
- 状态：在读 | 读完（<YYYY-MM-DD>）

## Summary

**一句话**：<作者的核心论点，一句话说完>

1. <要点>：<关键论据、数字或例子>
2. ...

## Comments

- [启发] ...
- [质疑] ...
- [联系] <与已学内容/已有笔记的关系，附链接>
- [行动] <想试、想改、想继续读的>
```

## 步骤

1. **先拿到原文**。读全文或完整字幕；只拿到片段时在来源行注明「仅基于部分内容」。没读到的不写。
2. **写 Summary**：
   - 「一句话」写作者的论点，不是话题（✗「讲了 Agent 代码质量」✓「把每次纠正变成 lint 和验证，而不是写进提示词」）。
   - 要点按原文逻辑排，3–7 条；每条带支撑它的证据（数字、例子、原话）。数字只抄原文，不估算。
   - 术语首次出现保留原词，必要时括号给中文。
3. **写 Comments**：
   - 每条用一个标签开头：`[启发]` `[质疑]` `[联系]` `[行动]`，没话说的标签就不写。
   - 区分来源：用户说的照记；Agent 自己的看法加 `(AI)` 标注。
   - `[联系]` 优先指向已有笔记、项目或任务（附路径或链接），而不是泛泛而谈。
   - `[质疑]` 要指出具体哪条论据弱、缺什么证据。
4. **边学边记**：分多次学习时，在同一份笔记里追加，不要另起一份。
   - 新内容补进 Summary 对应要点；用户的即时想法直接追加到 Comments。
   - 读完时重读一遍「一句话」，必要时改写，并把状态改为「读完」。
5. **存放**：在 Edges 仓库里用 `edges-note` 写入 `notes/`（标题用材料标题）；否则存为用户指定位置的 Markdown 文件。更新已有笔记时修改原文件，不新建。

## 不要

- 不要把观点写进 Summary，也不要在 Comments 里复述原文。
- 不要编造原文没有的数字、引语或结论。
- 不要写成长篇读后感；能一行说清的不写一段。
