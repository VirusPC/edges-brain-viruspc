# 04 榜单与图

撰写时只读 `issues/YYYY-MM-DD/` 里已经抓好的文件。不运行抓取脚本，不使用密钥。文件不在快照里，就去掉对应小节，原因写进说明文件。不要拿后来的数据冒充当时。

画图用同级 skill [`llm-arena-marked-chart`](../../llm-arena-marked-chart/SKILL.md)。词云脚本留在本 skill 的 `scripts/render_keyword_cloud.mjs`。

## 模型进展

顺序固定：Artificial Analysis → LLM Arena → OpenRouter → 模型发布。没有 Artificial Analysis 文件时，后面的小节仍从「二、模型进展」开头排，不要为了占位留空标题。

图下每张榜单独一句，给读者看这张榜相对上一期可核验的变化；没有对比就只说本期格局。不要写「数据取自」「快照」「抓取于」「统计窗口」「采样周」「红圈」「不圈」。来源、时间和缺项写进说明文件。图表仍要圈的名字，以及 Arena 的「榜单发布日」，写在紧挨这句的 `<!-- chart-meta -->` 里，读者看不见。下拉切换时每张图用自己的那句，不要三张共用一句。没有证据就不要写上升、下降或新进。

- Artificial Analysis：读 `aa-language-models.json`。按 `artificial_analysis_intelligence_index` 画 Top 15。红圈只圈窗口内 `release_date` 新发布、且出现在这张 Top 15 上的模型。免费接口缺的字段写进说明文件。
- LLM Arena：读当期 `llm-arena-*.json`。发布日与上一期正文采用的榜相同时，沿用那张图，读者那句写榜没有换。更新时重画。红圈是窗口内新发布且出现在这张榜上的模型。名次变化对照上一期正文实际采用的榜，不用 `prior_publish_date` 代替。
- OpenRouter：读三份排行 JSON。顺序是本周用量、编程用量、应用用量。某一张没有就只去掉那张。编程用量在读者那句里写明是 token 用量、不是质量榜。周环比、tokenizer 不能横比，只写说明文件。引用快照里的 “Source: OpenRouter … CC BY 4.0.” 也只写说明文件。
- 模型发布：读 `model-releases.json`。每个模型三行：价格、速度、效果。价格行在数字后写「更便宜第 x/y」，速度行写「更快第 x/y」，名次用快照里的 `rank` / `rank_of`。`rank` 不是正整数时不写名次。价格、速度或效果没有数字时，该行写「暂无」。正文数字和名次都以这份快照为准，不要用后来的报价或延迟重算。厂商自述和快照不同时，写明原文怎么说。

## 本周关键词

第一行是短关键词，同时作 PNG 的 alt。图放在这一行下面。权重写在章内 `<!-- keywords-cloud ... -->`。有 `weight` 就直接画。没有时：

```
mentionPart = min(mentions, 4) / 4 * 5
sourcePart = min(sources, 3) / 3 * 5
weight = clamp(round1(0.6 * score + 0.25 * mentionPart + 0.15 * sourcePart), 1, 5)
```

`mentions` 是本期 `####` 里出现该词的条数，上限 4。`sources` 用 [`scripts/source_hostnames.mjs`](../scripts/source_hostnames.mjs)。字号 `round(18 + (weight - 1) / 4 * 40)`。默认配色 `ink-sans`。找不到指定中文字体就停。

```bash
node scripts/render_keyword_cloud.mjs \
  --md ../../../ai-news/YYYY-MM-DD-ai-news.md \
  --out-svg ../../../ai-news/keywords-cloud-YYYY-MM-DD.svg \
  --out-png ../../../ai-news/keywords-cloud-YYYY-MM-DD.png
```

只给新的一期出图。

## GitHub Trending 图之外的名次

名次和 README 不在这一步重抓。前 5 的写法见 [选文](02-选文.md) 和 [排版](05-排版与开-PR.md)。读者看到的是这五名和上一期可核验的差别，不写订阅源、抓取时间或「不是官方榜」。那些留在说明文件。
