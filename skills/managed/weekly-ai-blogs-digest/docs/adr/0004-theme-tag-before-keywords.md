# 先写主线再抽词，每条主线一枚 tag

总结阶段在三路卡片汇合之后的顺序改为：本周总结，然后关键词，然后整页校验。每条主线有且只有一枚代表性 `tag`。关键词仍先从三路卡片抽词，再把这些 tag 加回 `keywords.json` 并提到权重下限。词云只读合并后的这份文件。

这覆盖 [0001](0001-weekly-overview-is-its-own-summary-product.md) 里「overview 排在关键词之后」和「撰写主线时要读关键词」。不覆盖 0001 的其余决定：overview 仍是独立产物，Agent 撰写，脚本只校验。页面顺序仍按 [0002](0002-overview-chapter-cloud-then-summary.md)：先词云，后总结。生成顺序和页面顺序不是同一件事。

出处：peng cheng 于 2026-11-24 确认。概览已在 0.0.8 上线，这一步直接改技能契约，不改站点，也不改数据仓库里的各期。

## Considered Options

- 继续先抽词、后写主线，让 tag 必须从已有关键词里选。否决：主线先定，tag 是写主线时选的代表性词，可以是抽词结果里还没有的新词。
- 用主线 tag 替换词云里的型号和产品名。否决：那些名字仍然是内容词，点它们会过滤页面，但不应冒充主线。
- 把每条主线 tag 都标成 `theme: true`。否决：`theme: true` 仍是抽词阶段选出的那一个概念高亮。提高权重不等于改主题高亮的含义。
- refs 为空的「本周无重要模型发布」也放进词云，并把 `targets` 放宽成可以是空数组。否决：词云里的每个词都要能指到内容 ID。这条没有引用，tag 留在 overview 上，固定写成「无重要发布」，不进入 `keywords.json`。
- 缺 tag 的 0.0.8 历史 overview 在技能升到 0.0.9 后直接校验失败。否决：那些文件仍锁在写出时的 0.0.8。tag 规则只作用于记录版本 >= 0.0.9 的 overview。这不是站点上缺 tag 仍能渲染的兼容路径，站点这次不改。

## Consequences

- 有模型卡片时，第一条写这周模型能力的发展方向，不是发布清单。型号要点名，收在这条方向里。文章不放进第一条。这条的 tag 是能力方向，不得是型号名。
- 其他主线的 tag 是这条线的主题，不得是单篇文章或单个项目、产品名。
- 正文逐字是「本周无重要模型发布」时，tag 逐字是「无重要发布」。refs 为空时不进词云。
- 已有的词：权重提到下限 5，该主线的 `refs.id` 并入 targets，不删原来的 targets，不改显示用的名字。新词：权重写成 5，targets 至少是这些 id，不写 `theme: true`。5 是现有权重刻度的上限。已经达到 5 的保持 5。
- 抽词阶段已经留下的型号和产品名不被 tag 替换或删除。合并发生在 16 个词的上限之后，列表可以因此变长。
- `theme: true` 在合并之前按原规则选定，合并不重新选举。
- 技能版本 0.0.8 → 0.0.9，只升 patch。
