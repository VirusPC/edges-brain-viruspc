术语表

这门课的「统一说法」。之后每一课都只用这里的词；同一个东西不换着叫。

规则：这些词保持英文——Agent、run、session、event inbox、worker、handler、timer、scheduler、memory、outbox、dispatcher、deferred tool call、auto mode、credential proxy。其他尽量用平常的中文。定义只说「它是什么」，一两句话。术语目前是「第 1 课引入」状态，等你测验过关后再按表现修订。

循环

always-on agent
一种对用户显得一直在、会自己决定何时行动、并能跨多次 session 管住上下文的 Agent。底下并不是进程一直醒着，而是睡了再醒的循环。 原文 · The cycle behind the always-on agent常驻进程、一直在跑的模型、24 小时不间断推理
run
Agent 醒来后的一段工作：收到一个事件，把活做完，再把这次发生的事存下来。做完就睡回去。 原文 · The cycle把 run 叫成 session；一次「开机」
session
一份消息和工具调用的 transcript。一次 run 发生在一份 session 里：接着先前工作的事件（例如用户答复）会续上已有 session，其余通常新开一份。 原文 · The cycle / Event inbox把 session 叫成一次醒来；聊天窗口（太泛）

五个原语

event inbox
一份耐用的待办事件列表（通常是一张表）。所有来源先把事件写进来，再由 worker 取出，而不是直接去叫 Agent。 原文 · Event inbox让每个来源直接调用 Agent；把 inbox 说成「就是消息队列」而不提要记录状态、可去重
handler
接收外来事件并写入 event inbox 的入口，通常是一个 HTTP 接口。它应当很快确认收到；更深的检查放到这次 run 里做。 原文 · Event inbox把 handler 和 worker 当成同一个东西
worker
从 event inbox 里读取待办事件、开一次 run、等它结束再把对应事件标成完成的后台服务。一个 inbox 同一时间只应有一个在工作的 worker。 原文 · Event inbox多个 worker 同时抢同一个 inbox；把 worker 叫成 Agent 本身
timer
存在独立耐用存储里、还没到期的提醒。分成两类：follow-up（Agent 给自己设的截止期限）和 schedule（已知节奏的重复任务）。timer 自己不会开 run。 原文 · Timers把还没到期的 timer 直接丢进 inbox；说 timer 会自己叫醒 Agent
follow-up
一类 timer：Agent 给自己设下的一次性期限，例如过一会儿去看有没有回音。到期后被标成完成，并写成 inbox 里的事件。 原文 · Timers和 schedule 混称「定时任务」
schedule
一类 timer：按已知节奏重复发生的任务，例如每天一份通讯。到期后要把下次时间改到下一回。 原文 · Timers和 follow-up 混称
scheduler
按固定间隔查看 timer 存储的后台服务：找出已到期的，按类别更新，再把事件写入 inbox 并叫醒 worker。可以用自建服务，也可用 durable execution engine。 原文 · Timers让 scheduler 直接开 run、绕过 inbox
memory
独立于 inbox 和 timer 的耐用存储，用来在多次互不相连的 run 之间保持连续。只应存放 Agent 查不回来的东西；已在别的系统里的，存一个指针。在产品里常表现为一目录文件，映射到数据库或对象存储，从而比 worker 活得更久。 原文 · Memory把外部系统整份镜像进来；把 memory 和 session 的 transcript 当成同一份东西
permissions
无人值守时约束 Agent 行动的那一层。每次工具调用都要决定：自己继续、拦住，还是等人批准。原文把它写成 always-on 风险最高的地方。 原文 · Permissions把 permissions 理解成「只开一个总开关」
outbox
一份待发出消息的表，和 event inbox 相对。需要控制发送节奏、或从投递错误里恢复时才值得单独做；多数情况一个 send 工具就够。 原文 · Outbox把逐步推理全部推给用户；把正式 outbox 讲成和 inbox 一样必不可少
dispatcher
读取 outbox 里待发消息、决定交哪些、再送给用户的后台服务。相当于 inbox 一侧的 worker。 原文 · Outbox把 dispatcher 和 worker 当成同一个进程角色而不加区分

记忆里的四类，以及上下文

user instructions
用户关于 Agent 该怎么行事的说明。单独放在一个文件里，每次 run 开头都加载。因为用户不总在场，这些说明必须能带到下一次。 原文 · Memory和 user notes 混在一个「备忘录」里不加区分
user notes
Agent 学到的关于用户的事，例如角色、偏好、以及用户给过的纠正。可以从一个文件开始，变多后拆成许多小文件，每次开头只加载索引。 原文 · Memory和 user instructions 混称
past messages
Agent 已经对用户说过的话，用来避免重复。可以单独成一个每次加载的文件，也可以由 worker 载入最近几条。 原文 · Memory把整份 session transcript 都叫成 past messages
task progress
每个进行中的任务一份进度文件，写清已经做完什么、还剩什么，好让新的 run 接着上次继续。和 user notes 一样，开头通常只加载索引。 原文 · Memory只把进度留在当前 session 的上下文里
context overhead
每次 run 开始时就要载入的那一层：system prompt、工具定义、以及 memory 文件。新 session 开头只有这一层加上触发事件；已有 session 还会带回先前 run 里的消息和工具调用。应当保持精瘦，并用 prompt caching 降低成本。 原文 · Inside the context window每次把全部记忆文件一股脑塞进上下文
dreaming
在 run 之外回顾过去的 session，用来整理 memory：替换过时条目，并找出只在许多次 run 里才看得出来的模式。本课只记这个名字，不展开。 原文 · Memory 补充 · The components of agent memory把 dreaming 讲成本课必须实现的步骤

权限与往返

credential proxy
原文在 credential store 一节里推荐的做法：把一个 proxy 放在 Agent 环境外面，给外发请求补上真实凭证。Agent 发出的请求不带凭证。本课用这个词指代该模式。 原文 · Permissions把密码或令牌放进 Agent 环境；把「credential store」理解成让 Agent 自己保管钥匙
auto mode
一种让 Agent 不必每次都等人点头的权限方式。Claude Code 里用 classifier 审查较高风险的动作，并挡住判定为危险的，好让模型改走更安全的路；最重要的决定仍要人看。 原文 · Permissions把 auto mode 说成可以代替人做最重要的决定
deferred tool call
把一次工具调用先挂起，等人补充说明或批准。这次 run 结束，session 保存在调用做到一半的地方；用户的答复作为事件回到 inbox，新的 run 再接着这份 session。等待期间 worker 仍可处理别的事件。 原文 · Permissions让当前 run 一直挂着空等；丢掉 session 再从头来
定义压缩自 William Hu · Building always-on agents。 dreaming 的展开见 The components of agent memory，本课不深挖。 随着你测验过关，定义会被改短，而不是另起一条。
