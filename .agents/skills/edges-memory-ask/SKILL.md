# Project Memory Ask

只检索当前项目的文件记忆，不写入。

## 结构

`AGENTS.md` 是系统作用域入口。打开它时，**本层硬约束已经写在文件里**——直接遵守，不要当成可跳过的索引，也不要再到记忆正文里找一份副本。其余链接登记本层材料与下层系统入口，一条链接可以跨好几层物理目录。Project 是主题组成容器，从 `INDEX.md` 继续组织材料，不要求另有 `AGENTS.md`。

一份 `AGENTS.md` 管它所在的目录连同整棵子树，越深越窄，下层是补充而不是覆盖。所以**一个文件相关的记忆，就是从记忆根到它所在目录这条链上的每一层**，叠加着看；每一层的硬约束都生效。

记忆按类型分成几份入口，每份只列该类型的记忆文件，类型入口再链接正文。上游可以经过材料清单和多层 Project，**不固定从 AGENTS 到正文的总跳数**；实际路径以索引为准，不硬拼 `.edges/memory`。尚未迁走、仍带 `edges-entries-*` 或 `edges-memory-type` 的类型目录 `AGENTS.md` 可以读取；`project-entries-*`、`project-memory-type`、`project-memory-entries` 不读。**每一跳都按链接后面那句说明挑，那句话就是判据**：入口后面写的是这份收什么，条目后面写的是这条讲什么。别按文件名猜，也别因为只有几份就全打开。

**按你实际读到的内容走。** 有几份入口、叫什么名字、记忆目录叫什么，都随实现版本变，产物里写的才是准的；冻结的只有「入口逐层套、类型入口链接正文、每项都带一句说明」这个形状（[`PROTOCOL.md`](../edges/references/memory/references/PROTOCOL.md)）。看不到本套结构就当这个项目没建记忆。本层清单还可登记任务和其他内容入口；已采用的 Memory Type 与种子同一跳规则；不要假定每层采用全部官方类型。类型索引、业务入口与普通 AGENTS 都是同一种节点，不要求 Memory 标记或独立职责资格。按本层与下层登记挑选发现路径，跨目录普通引用不改变所有权；适用祖先硬约束仍按实际工作范围叠加。引用技能的发现链接不扩散来源的全部约束。

记忆文件里 `description` 一定有，就是条目后面那句；`name` / `updatedAt` 有则可用（`updatedAt` 可能在顶层，也可能在 `metadata:`），没有就退回文件名、别按时间筛。

## 怎么查

- 用户提问或动手改代码前就查，不用等他说「搜索」。本轮已经查过、或者他只是让你按指定文案改字，跳过。
- **先定这次的工作范围**：用户点名的路径、当前在改的文件、上一轮动过的目录都算；只给了模块名或功能名就先定位到目录。然后取这几个目录各自那条祖先链上的记忆层，取并集——需要的多半已经在上下文里。不要从记忆根开始逐层猜，也不要打开工作范围外的兄弟层。范围实在定不出来，就只用记忆根那层。
- 用户指定主题 Project 时，保留原 scope 和祖先硬约束，从该 Project `INDEX.md` 的组成链接选择 Memory 类型；没有 Project AGENTS 不代表没有主题记忆。CLI 使用 `edges --scope <S> --project <P/projects/Q> memory list`，Project 路径相对 `S/.edges/projects`，不要把 Project 目录当新 scope。各 Project 的同名类型和 slug 独立，引用时保留返回路径。
- 需要 CLI 辅助发现时，`memory list` 列普通记忆，`skills list` 列技能；正文仍按索引说明选择打开。`--super` 换成 scope 直属材料的虚拟入口，`--all` 增加所选目录下的独立真实系统，Project 组成递归本身不需要 `--all`。完整组合和边界见 [查询入口与发现范围](../edges/references/memory/references/LAYOUT.md#查询入口与发现范围)，不要无条件扩大搜索。
- 先读索引，再按说明挑要打开的正文，不要因为索引小就把它列的条目文件全拉进来。
- 关键词自己从问题里提炼，不要照抄原句；复合问题拆开分别查。也可以对 `AGENTS.md` 链到的那个记忆目录直接跑 `rg -n -i <关键词>`。
- 先正面回答问题，答案末尾再列出这次真正参考过的记忆文件相对路径。什么都没查到就直说项目记忆里没有，然后用已有上下文继续，不要顺手去建。
