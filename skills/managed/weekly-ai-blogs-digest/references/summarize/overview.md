# 本周总结

汇合之后、关键词之前做。这一步只读本期 `summary/` 里已经精选的三路卡片，不读 `keywords.json`、`cleaned/` 或 `raw/`，也不把页面上看不到的条目写进来。

本周总结是独立产物。它不并进 `index.json` 或 `keywords.json`。`index.json` 只排章节和 ID。主线 tag 由下一步加回关键词，这一步不写 `keywords.json`。

## 契约

- 输入：`summary/articles/` 的 id、title、lede；`summary/projects/` 的 id、title、lede、purpose、change；`summary/models/` 的模型卡片（不含 `boards/`）以及卡片要点。有没有模型发布只看模型卡片，不含榜单。不读 `summary/keywords.json`。
- 输出：`summary/overview.json`。
- 生成命令：无。由 Agent 按下面的提示词写入 `summary/overview.json`。不要写生成脚本，也不要调用 LLM API。
- 校验器：`scripts/summarize/overview/validate.py`
- JSON Schema：`schemas/summary/overview.schema.json`

`text` 是纯文本，不含链接标记。`refs` 是 `{id, label}`。`label` 必须是对应 `text` 里的原文片段，并且是该条目的名字，不要把本条的 tag 写成某个条目的 label。字数是 `len(text)`，标点和英文都算 1 个字符。每条不超过 280 字。除「本周无重要模型发布」外，少于 120 字只警告，不因此失败。建议写到 180 到 280 字。

主线是 3 到 5 条。相关条目尽量聚在同一条里，能聚合就少写几条。第一条只写模型，不引用文章。本期 `summary/articles/` 至少有 3 篇时，至少一条 `kind=other` 的主线要引用不少于 3 个不同的文章 ID，而且这几篇要有共同主题。本期既有精选项目又有精选文章时，两类都不能整类缺席。

每条主线有且只有一个 `tag`：非空字符串，1 到 24 个字符，不能有首尾空白或换行。各条 tag 不得重复（忽略大小写）。tag 在写主线时选定，不必已经出现在抽词结果里，也不必出现在正文里。

- 有模型卡片时，第一条写这周模型能力的发展方向，不是发布清单。型号要点名，但收在这条方向里。这条的 tag 是能力方向，不得是某个型号名：不得与任一模型卡片 ID、榜单条目名、本条 refs 的 id 或 label 相同（忽略大小写和连续空白），也不得同时带有拉丁字母和数字。
- 没有模型卡片时，第一条仍是 `kind=model`。提示词要求正文逐字写成「本周无重要模型发布」、refs 为空、tag 逐字写成「无重要发布」。校验器不因「没有模型卡片但首条不是这句原文」失败；一旦正文就是这句，tag 必须是「无重要发布」。这枚 tag 表示没有重要发布，不是型号名。refs 为空时，下一步不把它写进词云。
- 其他主线的 tag 是这条线的主题，不得是单篇文章、单个项目或产品的名字：不得与任一条目的标题、ID、仓库名、模型名，或本条 refs 的 id、label 相同。

写完立刻校验：

```bash
python3 scripts/summarize/overview/validate.py issues/<生成日>
```

在本 skill 目录执行。通过才进入 [关键词](keywords.md)。这一步还不检查 tag 是否已经出现在 `keywords.json`：关键词尚未按本条 tag 合并。那一项在关键词校验和 [整页校验](check.md)。警告写到标准错误，退出码仍是 0。报错则退出码不是 0。

`skill.version` 写成当前 skill 版本。校验只要求它是 semver，且不能新于当前 skill。可以早于当前 skill：仍锁在 0.0.8 的历史 overview 没有 tag，不因此失败。tag 规则只在记录版本 >= 0.0.9 时生效。这不是「0.0.9 缺 tag 仍能通过」的旧格式分支。

## 提示词

你在写 AI 资讯周报「一、本周概览」的总结。关键词还没抽。不要读 `summary/keywords.json`。

输入只有本期 summary 里已经精选的内容：

- summary/articles/*.json 的 id、title、lede
- summary/projects/*.json 的 id、title、lede、purpose、change
- summary/models/*.json 的 id、lede 和模型卡要点

不要读 cleaned/ 或 raw/。不要写入页面上看不到的条目、数字或事实。

任务：写出 3 到 5 条本周主线。主线尽量把相关条目聚在一起。能聚合就少写几条，优先聚合而不是拆成 5 条薄卡片。不要为了凑条数把一件事拆开。每条不超过 280 字，建议 180 到 280 字。字数按去掉链接标记后的 Unicode 字符数计算，标点和英文都算 1 个字符。字数不够时，补上另一件已经发生、尚未写过的事，或补上条目之间还没写过的关系。不要把刚才那句换个说法再说一遍。

每条先想清楚这枚 tag，再写正文。tag 是一枚代表性词，1 到 24 个字符。各条不同。它不必已经在标题里出现过。

规则：

1. 第一条的 kind 必须是 model，且只写模型主线。有模型卡片时，写这周模型能力往哪里走，不要写成发布清单。型号要点名，收在这条方向里。这条的 tag 是能力方向，例如「进入工作流」，不得是某个型号名。本期 summary/models/ 下没有模型卡片时，第一条文本必须逐字写成「本周无重要模型发布」，refs 为空，tag 必须逐字写成「无重要发布」。不要把文章放进第一条。
2. 其余各条 kind 为 other。主线之间不要重复同一件事。第一条之后按重要性排序，不要按章节目录复述。每条的 tag 是这条线的主题，不得是单篇文章的标题，也不得是单个项目或产品的名字。正文里仍可点名那些文章和项目。本期既有精选项目又有精选文章时，这两类都不能整类缺席：other 主线的 refs 里要同时出现项目 ID 和文章 ID。当本期 summary/articles/ 至少有 3 篇精选文章时，至少一条 kind=other 的主线，其 refs 里要有不少于 3 个不同的文章 ID。这几篇必须有真实的共同主题。不要把不相干的文章硬塞进一条，只为凑满 3 篇。
3. 除「本周无重要模型发布」外，每条必须在 refs 里列出所依据的 summary 条目 ID，并给出这些 ID 在正文里出现的锚文字（label）。label 必须是 text 里的原文片段，并且是条目自己的名字。不要把 tag 当作 label。
4. 用完整、自然的句子写出这周实际发生的事，说明为什么值得看，以及条目之间有什么关系。句式要有变化。不要用「某某发布了，它重要是因为……」。不要写材料缺了什么，不要交代自己是根据哪类文件写的，也不要提醒读者别把一条读成另一类。

语气：只陈述已精选内容里的事实和它们之间的关系，不编造，不鼓吹，不靠元评论或换词重述凑字数。不确定就不要写。材料确实只够三条时可以只写 3 条。

`skill.version` 写成当前 skill 版本。输出写入 summary/overview.json，形状见 schema。

## 校验

报错（不能通过校验）：

- 不是 3 到 5 条
- skill.version 不是 semver，或新于当前 skill
- 去掉链接标记后，某条超过 280 字
- 首条 kind 不是 model，或首条之外还有 kind=model
- 本期有模型卡片，但首条写成「本周无重要模型发布」
- 引用 ID 不在本期 summary 的已知 ID 里
- 除「本周无重要模型发布」外，某条 refs 为空
- 某条 refs.label 在对应 text 里找不到
- 本期既有精选项目又有精选文章，但主线没有引用其中一类
- 本期 summary/articles/ 至少有 3 篇，但没有一条 kind=other 的主线引用了不少于 3 个不同的文章 ID
- 首条 refs 里出现了文章 ID
- 记录版本 >= 0.0.9 时：某条缺少 tag、tag 为空、tag 有首尾空白或换行、tag 与另一条重复
- 记录版本 >= 0.0.9，且正文就是「本周无重要模型发布」时：tag 不是「无重要发布」
- 记录版本 >= 0.0.9，且有模型方向可写时：模型主线的 tag 是型号名
- 记录版本 >= 0.0.9 时：其他主线的 tag 是单篇文章或单个项目、产品名

记录版本低于 0.0.9 时不检查 tag。仍锁在 0.0.8、没有 tag 的历史 overview 因此能通过。新写的 overview 必须记录当前版本，缺 tag 不能通过。

警告（校验仍通过）：

- 除「本周无重要模型发布」外，某条少于 120 字
- 同一 label 在 text 里出现多次，站点只链第一处
- 本期 keywords 里 theme 为 true 的词，总结正文完全没有出现

最后这条只在关键词文件已经存在时才会出现。写主线时不要为了它去读关键词。`theme: true` 是抽词阶段的概念高亮，不是主线 tag。

有无模型发布，以 `summary/models/` 下是否有模型卡片为准，不含榜单。不检查「本期没有模型卡片，但首条不是这句原文」。
