# 订阅端只读已上线的 latest.json，推送本周概览文字和当期页

一键订阅这一轮只定功能，不含站点 UI。订阅端 Agent 查最新一期时，只读站点上已经部署的 `latest.json`。这份文件在站点构建、部署时写入，只指向已经上线的期。不必先读 RSS。RSS 仍可供人订阅，但不写进 Agent 提示词的主路径。

提示词面向通用 Agent，用通用自然语言，不用平台专有语法。用户复制的是一句短句，加上说明页的 URL；完整指令放在说明页上。说明页的最终地址本轮不敲定。

查询由订阅端自己的 routine 执行：每天一次，周五晚和周六各加一次。只有发现新的已上线期号才推送，否则保持安静。这是订阅端的检查节奏，不是周五 09:00 那条发布 routine 的运行时刻。

每次推送返回本期「本周概览」里的文字，也就是本周总结、`summary/overview.json` 的 `text`，其中 `refs` 落到站内链接，再加当期页 URL。不要另写一套 3 到 5 条要点。词云是页面上的视觉组件，文字推送里不另贴图。

第一版不做个性化。所有订阅者收到同一份总结。说明页留一句：可以按关键词筛选。按关键词筛选推送内容另开任务，不在本决定里实现。

出处：第一轮 grill，2026-11-25。用户原话：「直接读latest.json是不是就够了」；「返回本周概览章节里的内容➕当期链接」。栏目名是「AI 资讯」，路径仍是 `/ai-news/`。第一章仍是「一、本周概览」，先词云后本周总结；页内跳转锚点仍按条目 ID 生成 `#entry-`，见 [0001](0001-weekly-overview-is-its-own-summary-product.md)、[0002](0002-overview-chapter-cloud-then-summary.md)。本篇不改这两处的含义。

新期何时算已上线、何时写进 `latest.json`，见 [0006](0006-ai-news-routine-ends-on-successful-deploy.md)。

## Considered Options

- 先读 `/ai-news/rss.xml`，再读该期结构化数据，并在构建时另写 `latest.json`。否决：用户确认只读已上线的 `latest.json` 就够了。RSS 继续给人订阅，不进入提示词主路径。
- 直接读 GitHub raw 或 jsDelivr 上的仓库 JSON。否决：仓库里的期可能已经合并、尚未部署，订阅端会推到站点上还没有的内容。
- 由 Agent 自行搜索最新一期。否决：搜索结果不能保证就是已经上线的那一期。
- 每次推送另摘 3 到 5 条要点，并以 `#entry-` 锚点作为主要产出。否决：要返回的是本周概览章节里的文字，加上当期页链接。`refs` 落到站内链接，不为推送再写一套要点。
- 把完整指令全部写进用户复制的那一段，或使用某一平台的专有语法。否决：提示词要能贴给通用 Agent；规则以后要改时，只改说明页。
- 第一版就按订阅者做个性化筛选。否决：本轮先定查询入口、节奏和返回内容。说明页只留一句，筛选另开任务。

## Consequences

- 现状：站点有 `/ai-news/rss.xml`，没有 `latest.json`。上线时间不固定，因为周五 09:00（Asia/Shanghai）的周报 routine 只打开数据仓 PR、不合并，数据仓合并也不会触发本仓 Pages 部署。`latest.json` 要在后续实现里于构建、部署时写入，并且只指向这次部署已经上线的期。本篇不添加这个文件，也不规定它的字段形状。本篇不规定部署路径；路径见 [0007](0007-subscribe-ui-copy-button-and-guide-page.md)。
- 订阅端确定最新已上线期，只读这份已部署的 `latest.json`。推送取该期本周概览的文字和当期页 URL，都来自已部署的站点，不读数据仓 raw。说明页写给通用 Agent 的步骤以这个入口为准。
- 推送正文来自当期 `overview.json` 的 `text`。`refs` 在推送里做成站内链接。另给当期页 URL。不附词云图。
- 说明页的地址、页面版式、站点上的复制按钮和订阅入口位置，本轮都不定。那些属于 UI，留到下一轮。
- 本篇只记录决定，不改技能版本，不改技能流程，也不改站点。`latest.json`、说明页和订阅提示词的落地留到 html-plan 确认之后。
