# 关键词

关键词在选文之前写入期次目录根上的 `keywords.json`。不读周报，不读入选后的 `####`，不读 `user-backfill.json`。页面只引用这份文件，不在选文之后重算。

```bash
node scripts/build_keywords.mjs \
  --issues-root /path/to/ai-news-data/issues \
  --issue YYYY-MM-DD \
  --out /path/to/ai-news-data/issues/YYYY-MM-DD/keywords.json \
  --snapshot-commit <这一期快照的完整 SHA> \
  --snapshot-ref <分支或 main>
```

输入是窗口内 `feeds.json`；同一 link 若有 `feeds-full.json`，用更长的 summary；`model-releases.json` 的 `models[].name`；更早 issues 的条目标题和正文。`date` 必须落在 `feeds.json` 的 `window` 里。`linux-do-welfare` 不计数。没有更早目录时，`gaps` 写明，不假装已经排除过窗口前的名字。

选词只认快照里的连续片段，或官方名。不把两件事拼成一个新词，也不把英文译成快照里没有的中文。

- 新模型：官方名，以及发布标题里的型号。`score` 为 5。更早标题或正文里已经出现过的不收，预览过再正式上线也不再当新模型。`is now available in` 不抽。评测标题不抽模型名。名字里带 Security、Review、Code、Evaluation、Benchmark、Test、Tool 的算产品，不算模型。
- 新产品：同一类标题里、窗口内第一次公开、而且不是阻断名单上的整词。`score` 为 4。名单以 `scripts/build_keywords.mjs` 的 `BLOCKED_PRODUCTS` 为准，整词相等才排除。
- 概念：至少两条标题里原样出现的说法。`score` 为 3。

`mentions` 是窗口内条目数。`sources` 是这些条目链接的 hostname 数，同一主机只算一次。mentions 为 0 不收。热度写入 `weight`，算法在 `scripts/keyword_cloud_style.mjs`：

```
mentionPart = min(mentions, 4) / 4 * 5
sourcePart = min(sources, 3) / 3 * 5
weight = clamp(round1(0.625 * mentionPart + 0.375 * sourcePart), 1, 5)
```

主题只从概念里选：`sources` 更高的优先，相同再比 `mentions`，写在那一条的 `theme: true`。没有概念就不标。清洗可以把已选中的那条写成读者表达，证据短语必须就是这条概念。

`words` 每项有 `word`、`kind`、`score`、`mentions`、`sources`、`weight`。feeds 或官方名变了就重跑这条命令。选词规则变了也重跑，用已经落盘的条目，不重抓文章。更早条目的标题或正文变了，才重判「窗口前是否已经公开」。更早一期的榜单不传入。
