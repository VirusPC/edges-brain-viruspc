# 页面

总结和榜图说明都完成后，写 `products/page.json`。这张表要能单独渲染整页，不靠没写下来的挑选或临时补句。正文、链接、关键词、榜图说明和模型三行都来自已经落盘的表或文件；本节点只排章节并记下引用。站点负责版式、词云排版和榜图绘制，不另选文，不另写总结，不另抽关键词。

`node` 是 `page`。`inputs` 至少引用 `products/selection.json`、`products/summaries.json`、`products/boards.json`、`keywords.json`。用到模型数字时再引用 `model-releases.json`。`rules.path` 指向本文件。`window` 有 `since`、`until`、`generated`。

`chapters` 按这个顺序，标题用这六个：

1. 一、本周关键词。只引用 `keywords.json`。`words` 为空或文件不在，就 `omitted: true` 并在 `notes` 写原因，不在这里重算词。
2. 二、模型进展。按 `boards.json` 的行排榜，再按选文里归到模型进展的链接排模型条目。条目的总结、三行数字和发布要点读 `summaries.json`。
3. 三、项目开源。先是 weekly/all 前 5，再是其他 GitHub 仓库。只放链接，卡片文字读总结表。标题下面不要写概括前五名字的介绍句。
4. 四、精选文章。分组顺序是国内模型厂、国外模型厂、国内非模型厂、国外非模型厂。空组不写。组内公司顺序用 `site/src/lib/ai-news-category-filter.mjs`。
5. 五、精选推文。`status` 为 `wip`，没有条目。
6. 六、精选播客。同样 `wip`，没有条目。暂时不采集推文和播客，也不为此改 OPML。

六个标题都留在 `chapters` 里。没有内容的章节写 `omitted: true`，推文和播客保持 `wip`。缺口、来源和过程说明放在 `notes`，不放进读者 caption。

`provenance` 记下这次的 `rules.commit`，以及数据快照已经落库的 `data.commit`。没有的一侧写 `null`。不填 `main`、短 SHA，也不填周报稿自己的提交。

校验：

```bash
node scripts/validate_products.mjs /path/to/ai-news-data/issues/YYYY-MM-DD
```

在站点改读 `page.json` 之前，周报稿仍是 `ai-news/` 里的 markdown。稿里的选文、总结、关键词和榜图说明必须来自已经写好的表，不在写稿时另选或另编。
