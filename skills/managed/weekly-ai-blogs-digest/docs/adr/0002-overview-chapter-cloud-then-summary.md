# 第一章先词云后总结，并用条目 ID 做稳定锚点

第一章改名为「一、本周概览」，先放词云，再放本周总结。总结写 3 到 5 条主线，有材料时尽量写 4 或 5 条；每条不超过 280 字，建议 180 到 280 字。第一条永远是模型主线，模型单独占一条；没有重要模型发布的周，第一条写「本周无重要模型发布」。每条都链接到正文条目。跳转锚点按条目 ID 生成，不沿用现在的标题 slug；跳转后目标卡片短暂高亮。总结里提到的词不在词云里联动高亮。

每条 100 字是第二轮 grill 的原决定。用户在实现之后改了这条：100 字覆盖不够，语气也僵。2026-11-23 改为上面的篇幅，并要求用完整、自然的句子说明为什么值得关注，或和其他条目是什么关系，不要套「某某发布了，它重要是因为……」。本期既有精选项目又有精选文章时，这两类都不能整类缺席。除那句「本周无重要模型发布」外，少于 120 字只警告。版本仍是 0.0.8，不另升 patch。

词云在前是用户改过的决定。出处：第一轮 grill，2026-11-23。推荐方案原是先总结后词云，用户改成了先词云后总结。

## Considered Options

- 先总结后词云。否决：用户要求先看热词，再读主线。
- 沿用标题 slug 作为页内锚点。否决：现有 id 来自标题，标题一变就会失效；模型卡尤其对不上，例如条目 ID 是「GPT-6.2 Astra」，页面 id 却来自博客标题。
- 总结里出现的词在词云中联动高亮。否决：先保持简单，不改现有词云画法。出处：第一轮 grill，2026-11-23。

## Consequences

- 站点要把「一、本周关键词」改为「一、本周概览」，插入词云时必须保留下方的总结列表。
- 每张卡片需要由条目 ID 派生的稳定 id。标题 slug 可留给目录，但本周总结的链接不再用它。
- 字数按去掉链接标记后的 Unicode 字符计算，标点和英文都算 1 个字符。若采用已定的「正文与 refs 分开存」，字数就是 `text` 的字符数。上限 280；少于 120 且不是「本周无重要模型发布」时警告。

## 页面样式（易改，不单独成 ADR）

以下都在第二轮 grill 定下，2026-11-23。其中模型条标签是用户改过的决定。

- 编号用阿拉伯数字 1. 2. 3.
- 模型那条不加「模型」小标签，只靠排在第一条。推荐方案原是加小标签，用户改成了不加。
- 不加「本周主线」小标题。章名已经是本周概览。
- 字号与正文一致，不用备注卡的 0.8em。
