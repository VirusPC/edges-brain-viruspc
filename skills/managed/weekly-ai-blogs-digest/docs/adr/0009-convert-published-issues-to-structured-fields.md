# 已发布各期用机械抽取迁到新格式，缺段补写，尽量保留已发布措辞

把六期已发布数据改成 0008 的字段时，有两条路：用 0.0.12 技能全部重生成，或从现有 `text` 抽取字段。决定走机械抽取：能从现有正文拆出来的字段保留原措辞；缺的五段再补写，补写直接写入字段，不做任何标记。不为了迁格式而重写已经发布的卡片。本周总结和关键词都不重算，已发布的第一章保持原样。

出处：第一轮与第二轮 grill，2026-11-27。用户把推荐的「六期全部重生成，并重算 overview 和关键词」改成了「从现有 text 机械抽取字段，缺段再补写，尽量保留已发布措辞」。第二轮又把推荐的 `filled` 标记改成「补写进字段，不做任何标记」，并确认 overview 和关键词都不重算。

## Considered Options

- 用新技能把六期全部重生成，模型直接写字段。否决：措辞会整页改掉，和「尽量保留已发布措辞」冲突。更早几期项目卡缺少五段、个别导语字段已经写坏，这些问题用抽取加补写就能处理，不必整期重跑。
- 11-27 机械抽取，更早各期重生成。否决：同一栏目里各期措辞来源不一致；用户要的是尽量保留已发布措辞，不是按期混用两种办法。
- 补写时用 `filled` 数组记下哪些段是后补的，或在正文前加「原文未写，此处补写：」。否决：第二轮确认不做任何标记。可见前缀会改卡片外观；用户选择把补写和原措辞同等写入字段。
- 迁移后重算 overview，或只重算关键词。否决：第二轮确认两者都不重算，已发布的第一章保持原样。补写段落要等到以后按现行技能重跑，才会进入词云。

## Consequences

- 这次抽取是一次性的数据迁移，不是站点里的兼容层。迁完之后，站点只读字段，校验器不再解析 `text`，也不再保留 0.0.11 的文本解析门槛。
- 10-23、10-30、11-06 的项目卡和 11-13 里不完整的五段需要补写。补写进 `sections`，不写 `filled`，也不在正文里加说明。
- `overview.json` 和 `keywords.json` 保持迁移前的内容。以后若用户要求「重跑」，仍按现行技能从头生成，与这次迁移不是同一件事。
