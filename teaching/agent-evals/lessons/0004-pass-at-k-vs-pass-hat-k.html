Lesson 04 · ~5 分钟

多 trial：至少一次 vs 次次都成

Agent 有随机性。同一 task 多跑几次时：pass@k 问「k 次里有没有一次成」；pass^k 问「k 次是不是全成」。选型看产品能不能接受重试。

主文献：Anthropic · Demystifying evals for AI agents · 2026-01-09

← 第 3 课 第 5 课 → 术语速查 原文

先点开：用前三课四个词把场景钉住（延迟复习）

对同一 task 跑多次 trial。每次留下 transcript（也叫 trace / trajectory）与可核对的 outcome。grader 判定每次 trial 成败后，再用 pass@k / pass^k 汇总「多试几次」的故事——不是另起一套成功定义。

这一课你要带走什么

会按使用场景选指标：容许多次尝试找一个解 → pass@k；用户期望每次都稳 → pass^k。并记住：这是同一任务重复 trial，不是工作流里连续 k 个子步骤。

两个指标

pass@k 至少一次
k 次尝试里至少有一次成功的可能性。k 越大通常越高（更多「射门机会」）。coding 常关心 pass@1（第一次就要对）。
pass^k 次次都成
k 次尝试全部成功的可能性。k 越大通常越低（一致性更难）。客服等「每次都要可靠」的场景更贴切。
原文对照 k=1 时两者相同（都等于单次成功率）。k 变大后故事相反：pass@k 趋向升高，pass^k 趋向降低。原文写到约 k=10 时，一边接近 100%、一边接近 0%——这是趋势描述，不是你套件的实测分数。

假设示例（标清：教学用，非你系统实测）

若某 task 单次成功率 p=0.8，且各 trial 独立同分布

  1. pass^3 ≈ 0.8³ = 0.512（51.2%）——三次全成并不轻松。
  2. pass@3 ≈ 1 − (1−0.8)³ = 1 − 0.008 = 0.992（99.2%）——三次里至少一次成则很容易。
  3. 原文另有示意：p=0.75、k=3 时 pass^3 ≈ (0.75)³ ≈ 42%。同一简化假设。

局限（必读）：上面的乘方 / 补概率只在「同一 task、trial 近似独立同分布」时好算。真实评测里，不同 task 难度异质，trial 可能因环境/缓存相关，重试还有时间与金钱成本——不要把简单公式当成普适估计器。应用时以你实测的多 trial 结果为准。

怎么选

  • 工具允许「多生成几个候选、有一个过测就行」→ 看 pass@k（常先看 pass@1）。
  • 用户每次会话都期望成功、不能靠「再试一次」掩盖翻车 → 看 pass^k。
  • capability 爬山与 regression 守城都可参考；越在意稳定性，越该盯 pass^k（或多次全过）。
易错点 pass^k ≠「一个长工作流连续 k 步都对」。它是：同一 task，重复 k 次 trial，要求这 k 次 outcome 全过。
