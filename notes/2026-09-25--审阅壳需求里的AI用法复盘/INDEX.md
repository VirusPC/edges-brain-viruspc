# 审阅壳需求里的 AI 用法复盘

> 2026-09-25。复盘 Tasks 审阅壳从桌面三列（#126）到窄屏合入（#133）时，助手怎么举证、怎么锁决策、怎么交接。界面规格以 ADR 为准，本文不重写规格。

【背景】

Tasks 审阅壳先在桌面做成三列，并随 PR #126 合入。人换到手机上看，中间看板几乎用不了。后来按窄屏适配改完，由 PR #133 合入。用户要复盘的是这段需求里有意思的 AI 用法：谁负责举证、谁先把否决项写死、谁改代码、谁验收、谁收口看板。这篇笔记给没看过原对话的人独立阅读。布局尺寸、菜单文案和完成标准仍以 ADR 0022、ADR 0023 和两张任务卡为准。

【过程】

#126 的三列壳合入之后，Coding / 全栈在 box 上把视口设成 390×844，截图证明整页横向溢出，中间状态板几乎不可用，详情也点不开。用户只说「记个 task」，没有当场要求改界面。任务记录员把这件事落成窄屏卡，并把这组证据图写进卡里，供以后派发时核对。

派发实现之前走了 grill-with-docs。2026-09-24 锁下 ADR 0023。决定仍是同一份壳：窄于 768 像素改为纵向长滚动，项目筛选、状态板、详情接在同一页里往下排。抽屉分页、把三栏挤进窄屏、另做一套壳，以及给审阅页加 `--mode`，都写进否决项。完成标准一并写进 ADR，包括 390×844 以及任何窄于 768 像素的宽度上整页不得横向溢出。这一轮 ADR 写明先锁决策，不改 React。

实现由云端 Coding agent 开 PR #133。中间多轮改吸顶、滚动和锚定，让窄屏既能滚到顶，也能滚到底、滚到详情。证据是 Artifacts 上的预览 HTML，加上窄屏滚顶、滚底的截图。设计验收在 390 视口上给出 r9.1 PASS。

角色按职责切开。实现方不改看板状态。#133 合入之后，由任务记录员核对看板：相关 UX 卡当时已经是 done，不必再搬状态夹。写回仓、语义检索等 backlog 刻意留在原处，不借这次合入一起改。

过程里还记下两条协作事实。观感上的 validate 可以派给非实现方，这一轮由视觉同学做。中途若 Artifacts 已经发布、正要交给设计，这一步被打断，预览链就发不出去，下一位会悬空；约定是同一轮做完交接，或者立刻报阻塞。

【所学】

先举证再开卡。桌面可用和手机可用是两件可以分开核对的事。助手用目标视口截图，把「中间板出不去、详情点不开」变成卡上的证据，后面的人才能按事实派发。口头说一句「要适配」，派发出去仍不知道坏在哪。

布局争议大时，grill 和 ADR 要先于写码。挤栏宽、第二套壳、`--mode` 这些路一旦写进否决项，实现 agent 的发挥边界就清楚，不容易在写代码时把产品做成另一套。完成标准写在 ADR 里，验收也有同一份尺子。

窄屏和桌面是同一产品上的两个断点。窄屏换的是信息架构：同一份壳改成纵向长滚动。实现边界因此落在断点以下怎么排，而不是新开一个入口或一种模式。

多助手流水线要按职责切开。记录员维护看板真相，实现维护 PR，设计做观感验收。实现方不改 `edges-tasks-status`，合入后的状态以记录员核对为准，减少两个人同时改同一张卡。

预览链是协作介质。给手机和设计看的，是可以打开的预览页，加上滚顶、滚底的截图。只在 IDE 里说「我改好了」，验收方无法在目标视口上复看。验收标准可以写成可核对的数字和轮次，例如 390 视口、r9.1。

Render-only 是硬边界，要在卡和 ADR 里反复写。审阅壳只渲染页面，改 project 之后仍走 Copy JSON，再由人用现有命令落地。助手改着 UI 很容易顺手把结果写回 git。卡和 ADR 反复写「不写回 git」，这条边界才在多轮实现里守得住。写回仓因此继续留在自己的 backlog 上。

【行动指南】

若桌面功能看起来已经完成，但用户主要在手机上用：则先让实现助手在目标视口截证据，把溢出和点不开的位置写进卡，再决定开卡或改卡。不要凭「桌面已合入」直接开写。

若布局怎么摆争议大：则先 grill-with-docs，把否决项和完成标准写进 ADR，并写明这一轮是否允许改代码。决策锁上之后，再派云端 agent 改实现。

若需要设计或真人在手机上看：则同一轮打出可打开的预览链，连同目标视口的滚顶、滚底截图交给验收方。本地 build 通过只说明编译过了，不能代替对方打开页面。

若实现助手汇报 PR 已合入：则由任务记录员扫相关看板卡收口。实现方默认不改 `edges-tasks-status`。卡已经是 done 就不必再搬家；写回仓、语义检索等无关 backlog 保持不动。

若交接停在发布预览之前，或发布之后还没交给验收方：则立刻说明阻塞点、影响和下一步，或者在同一轮把预览发出去。不要把「正在发布」挂在后台，等对方来问才继续说话。
