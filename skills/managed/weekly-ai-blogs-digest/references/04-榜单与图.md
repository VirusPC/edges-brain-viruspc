# 04 榜单与图

撰写时只读 `issues/YYYY-MM-DD/` 里已经抓好的文件。不运行抓取脚本，不使用密钥。文件不在快照里，就去掉对应小节，原因写进说明文件。不要拿后来的数据冒充当时。

画图用同级 skill [`llm-arena-marked-chart`](../../llm-arena-marked-chart/SKILL.md)。词云脚本留在本 skill 的 `scripts/render_keyword_cloud.mjs`。

## 模型进展

榜单小节顺序固定：Artificial Analysis → LLM Arena → OpenRouter。模型条目接在这些小节后面，每条用 `####`，不要再写「模型发布」标题。没有 Artificial Analysis 文件时，后面的小节仍从「二、模型进展」开头排，不要为了占位留空标题。

图下每张榜单独一句，给读者看这张榜相对上一期可核验的变化；没有对比就只说本期格局。不要写「数据取自」「快照」「抓取于」「统计窗口」「采样周」「红圈」「不圈」。来源、时间和缺项写进说明文件。图表仍要圈的名字，以及 Arena 的「榜单发布日」，写在紧挨这句的 `<!-- chart-meta -->` 里，读者看不见。下拉切换时每张图用自己的那句，不要三张共用一句。没有证据就不要写上升、下降或新进。

- Artificial Analysis：读 `aa-language-models.json`。按 `artificial_analysis_intelligence_index` 画 Top 15。红圈只圈窗口内 `release_date` 新发布、且出现在这张 Top 15 上的模型。免费接口缺的字段写进说明文件。
- LLM Arena：读当期 `llm-arena-*.json`。发布日与上一期正文采用的榜相同时，沿用那张图，读者那句写榜没有换。更新时重画。红圈是窗口内新发布且出现在这张榜上的模型。名次变化对照上一期正文实际采用的榜，不用 `prior_publish_date` 代替。
- OpenRouter：读三份排行 JSON。顺序是本周用量、编程用量、应用用量。某一张没有就只去掉那张。编程用量在读者那句里写明是 token 用量、不是质量榜。周环比、tokenizer 不能横比，只写说明文件。引用快照里的 “Source: OpenRouter … CC BY 4.0.” 也只写说明文件。
- 模型条目：读 `model-releases.json`。不要加「模型发布」小标题。每个模型三行：价格、速度、效果。价格行在数字后写「更便宜第 x/y」，速度行写「更快第 x/y」，名次用快照里的 `rank` / `rank_of`。`rank` 不是正整数时不写名次。价格、速度或效果没有数字时，该行写「暂无」。正文数字和名次都以这份快照为准，不要用后来的报价或延迟重算。厂商自述和快照不同时，写明原文怎么说。效果行只写智力指数，以及原文和榜不一致的那句。定位写在下面的发布要点里，效果行不写「适合」。

卡片由站点插在标题下面。紧接着写「发布要点」，不要再写一段没有小标题的长文。3 到 4 条短句，每条开头加粗一个领词，按顺序取用：上线、定位、成绩，最后一条是可用或实测。没有第三方产品实测就写可用。关键数字用一处 `<mark class="note-card-hl">` 包住原句里已有的数字。链接放到最后一行，写成「来源：」。只写这条原文里已经有的事实。`<aside>` 到 `</aside>` 中间不要空行。外框和卡头用和备注卡同一套 `info-card`。卡头是列表图标加「发布要点」。

```html
<aside class="info-card">
<p class="info-card-label"><svg class="info-card-icon" xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round" aria-hidden="true"><path d="M8 6h13"></path><path d="M8 12h13"></path><path d="M8 18h13"></path><path d="M3 6h.01"></path><path d="M3 12h.01"></path><path d="M3 18h.01"></path></svg><span>发布要点</span></p>
<ul>
<li><strong>上线</strong> 哪一天、在哪发布。</li>
<li><strong>定位</strong> 它相对已有模型或产品的位置。</li>
<li><strong>成绩</strong> 原文里的数字，用 <mark class="note-card-hl">一处数字</mark> 标出来。</li>
<li><strong>实测</strong> 第三方产品测试。没有就改成「可用」，写在哪能调用。</li>
</ul>
<p class="info-card-note">来源：<a href="{{url}}">{{标题}}</a></p>
</aside>
```

## 本周关键词

词和权重在采集时已经写入 `keywords.json`。这一步只展示这些已经生成的词，不在选文或总结之后现算，不改词，不重算 mentions，也不从周报 `####` 现数一遍。文件不在，或 `words` 为空，就去掉这一章，原因写进说明文件。依赖见 [数据流](00-数据流.md)。

章节里只留注释，不写文字词表，不放图片：

```
<!-- keywords-cloud
[{"word":"…","kind":"model","score":5,"mentions":1,"sources":1,"weight":3.6}]
-->
```

数组是 `keywords.json` 的 `words`，去掉 `hosts` 和 `example` 也可以，`word`、`weight` 必须在，主题那条还要有 `theme: true`。这是快照的副本。站点优先读已经带 `theme` 的 `issues/YYYY-MM-DD/keywords.json`；快照还没有主题字段时，用这段注释。用 d3-cloud 在构建时排版，种子 1，旋转角 0。测量字重固定 Noto Sans CJK SC 700，中档和低档只在画出时改成常规字重。不提交 SVG 或 PNG。

热度在采集时按下面的公式写好，放进 `weight`。撰写时不要再算。种类分不进热度，也不决定谁是橙色主题。

```
mentionPart = min(mentions, 4) / 4 * 5
sourcePart = min(sources, 3) / 3 * 5
weight = clamp(round1(0.625 * mentionPart + 0.375 * sourcePart), 1, 5)
```

`score` 仍只说明种类：新模型 5，窗口内新公开的产品 4，概念 3。支撑词的字号是 `round(18 + (weight - 1) / 4 * 40)`。

主题是清洗时写在一条词上的 `theme: true`。一篇只有一个。渲染只认这个字段：主题用顶档，字号比最热的支撑词大 8px。没有这个字段时不把最热的词涂成顶档。支撑词按热度分高、中、低。同一热度同一档，不按字母序配色。不同热度按高、中、低尽量均分，多出来的名额给更热的档。

- 顶：赭石加粗。亮色 `#b4541f`，暗色 `#e09a62`。
- 高：墨色加粗。亮色 `#1c1b19`，暗色 `#f3ece1`。
- 中：常规。亮色 `#5c574e`，暗色 `#c4bdb2`。
- 低：常规，比中档更浅。亮色 `#746f65`，暗色 `#9c958a`。

图不铺底、不画外框。底是透明的。外框是站点的手绘轮廓，用 `#rough`（`baseFrequency` 0.03，`scale` 2.2），不进图片。亮色和暗色走 CSS 变量。手机和桌面都看这张图：宽 100%，字不能被裁掉。

## GitHub Trending 图之外的名次

名次和 README 不在这一步重抓。前 5 的写法见 [选文](02-选文.md) 和 [排版](05-排版与开-PR.md)。标题是 `GitHub Trending（weekly / all 前 5）`。标题下面不要写概括前五名字的介绍句，例如「这期看的是一周榜，前五是……」。标题之后直接写各仓库卡片。和上一期可核验的差别写进说明文件。刚从 daily 换成 weekly 时，不要拿 daily 前五和 weekly 前五做环比。不写订阅源、抓取时间或「不是官方榜」。那些留在说明文件。
