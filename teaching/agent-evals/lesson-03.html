两套题库：爬山 vs 守城

capability（质量）eval 问「还能做什么」——起步 pass 该偏低；regression eval 问「以前会的还会吗」——应接近 100%。爬上去的题，可以毕业进回归套件。

这一课你要带走什么

能分清两套 eval 的目的与目标 pass rate，并知道：高 pass 的 capability 题可以 graduate 成持续跑的 regression——从「能不能做」变成「还能不能稳定做」。

一张对照表

capability / quality eval 能力 / 质量
问：What can this agent do well？挑还做不好的题当小山爬。起步 pass rate 应偏低，才有改进信号。
regression eval 回归
问：Does the agent still handle what it used to？保护已会的行为。pass rate 应接近 100%；掉分 = 坏了。
同时跑 爬 capability 时也要跑 regression，避免「这边修好、那边回退」。上线优化后，高 pass 的 capability 可毕业进回归套件持续守住。

例子 A：订票客服

两套题，不同目标分

  1. capability：复合改签 + 政策边界 + 生气用户——当前常挂，pass 偏低，专门用来爬山。
  2. regression：查订单、简单退款、身份校验——早已稳定，套件应近满分；一掉就报警。
  3. graduate：某道「拒改签 basic economy」从常挂练到连续近满分 → 迁入 regression，不再当能力前沿。

例子 B：改文件 / coding

同一仓库，两种压力

  1. capability：多文件重构、罕见安全漏洞、长程调试——难、低 pass，推动 harness / prompt / 模型升级。
  2. regression：空密码拒绝、基础 lint、常见 CRUD 修复——应几乎次次过；用来防「为了难题牺牲旧能力」。
  3. 若整份 capability 套件已近饱和，改进信号变弱——要加难题，或把已稳的题毕业走。

原文举例 SWE-bench Verified 曾从约 30% 爬到 >80% 近饱和；以你自己套件的实测为准。

实操口诀

  • 新能力 → 先写低 pass 的 capability 题（eval-driven）。
  • 已稳定 → 放进 regression，CI 里常跑。
  • 只看「总分涨了」不够：要分开看两套，避免用难题掩盖回退。
  • 100% 的 capability 不再教你进步——该加难或毕业。
