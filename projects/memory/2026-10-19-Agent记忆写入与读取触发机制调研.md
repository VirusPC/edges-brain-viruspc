# Agent 记忆写入与读取触发机制调研

> 整理日期：2026-10-19（Asia/Shanghai）
> 来源：调研（官方文档、源码、论文；核查日期 2026-10-19）
> 用途：回答「agent 什么时候写记忆、什么时候读记忆、由谁决定」，给 edges Project Memory 的写入/召回设计做对照。
> 原则：每条结论附一手来源链接；来源未写明或只见于第三方的内容标 **未核实**。
> 相关笔记：同目录 `2026-10-14-Agent-Memory-Dreaming调研.md`（后台巩固专项）、`2026-10-17-Letta与Devin-git记忆的接入检索与沉淀.md`。

## 1. 各系统机制

**Claude Code**（文档版本约 v2.1.28x）
- 读取：启动时把工作目录及所有上级目录里的 CLAUDE.md / CLAUDE.local.md 全部拼进上下文；子目录里的 CLAUDE.md 要等 Claude 读/写/编辑该目录下的文件时才加载；带 `paths` 的 rules 在 Read/Write/Edit 碰到匹配文件时才加载。这些文件以“系统提示之后的一条 user 消息”注入。`/compact` 之后，项目根目录的 CLAUDE.md 会重新注入。https://code.claude.com/docs/en/memory
- Auto memory（默认开启）：每次会话都会预加载 `MEMORY.md` 索引（前 200 行或 25KB，以先到者为准）；各主题文件不预加载，Claude 需要时用普通文件工具按需读取。由 Claude 自己决定写什么（user/feedback/project/reference 四类，可推导的信息不写）。用户说“remember…”时写入 auto memory；说“add this to CLAUDE.md”或用 `/memory` 时改 CLAUDE.md。harness 在 MEMORY.md 超过限制时会返回错误，要求 Claude 精简（这一步由代码强制）。同一出处。
- `#` 快捷键：当前文档未提及，现行版本是否还有此功能 **未核实**。
- API memory tool（`memory_20250818`）：这是客户端工具，读写都由模型通过 tool call 自己决定。启用后 API 会自动往系统提示里加一段：“ALWAYS VIEW YOUR MEMORY DIRECTORY BEFORE DOING ANYTHING ELSE… ASSUME INTERRUPTION”。也就是说，读写时机完全由提示词驱动。https://docs.claude.com/en/docs/agents-and-tools/tool-use/memory-tool

**OpenAI Codex / ChatGPT**
- AGENTS.md：每次运行（TUI 每次会话）开始时构建一次指令链：全局 `~/.codex` → 从 Git 根目录走到 cwd，每个目录最多取一个文件（override 优先），拼接到 32KiB 为止。全部预加载，没有懒加载。https://developers.openai.com/codex/guides/agents-md
- Codex memories：实验性功能，默认关闭（`[features] memories=true`）。写入方式是后台流水线：会话空闲足够久才处理，跳过短会话，脱敏 secrets，先做逐会话 extract 再做全局 consolidation（模型可分别配置），配额余量低于阈值时跳过。`use_memories` 控制是否把记忆“注入”后续会话。注入是全量注入还是检索后注入，**未核实**。https://learn.chatgpt.com/docs/customization/memories
- ChatGPT：saved memories 有两个来源，一是用户明确要求，二是 ChatGPT 自己判断“有用”后保存。Reference chat history 则是“在可能改善回答时”才去查找相关上下文，并非每轮都检索。https://help.openai.com/en/articles/8590148-memory-faq 。内部 `bio` 工具名称和系统提示原文没有官方文档，**未核实**。

**Mem0**
- 论文（arXiv 2504.19413，2025）：每收到一对消息 (m_{t-1}, m_t) 就触发一次 extraction：LLM 结合会话摘要和最近 10 条消息抽取候选事实。然后对每条事实检索 top-10 相似记忆，再由 LLM 通过 tool call 选择 ADD/UPDATE/DELETE/NOOP。https://arxiv.org/abs/2504.19413
- 现行 v3 算法：已改为单次 LLM 调用，只做 ADD（不再有 UPDATE/DELETE），新旧事实通过 `linked_memory_ids` 关联；search 改为语义 + BM25 + 实体的混合检索，“哪条最新”在检索阶段处理。https://docs.mem0.ai/migration/platform-v2-to-v3 ，https://docs.mem0.ai/changelog/sdk 。v3 的发布日期（第三方摘要称 2026-04）**未核实**。
- 谁调用：用 SDK 时，由开发者代码决定何时调用 `add()`/`search()`（文档建议“学到有用信息时 add”）。用 MCP 时，由 agent 自己决定何时 save/search（“decide for itself when to save something, look something up”）。https://docs.mem0.ai/core-concepts/memory-operations/add ，https://docs.mem0.ai/platform/mem0-mcp

**其他系统**
- **MemGPT/Letta**：读写全部由模型自主决定（“entirely self-directed”）。working context（core）始终在 prompt 中；archival/recall 存储要通过函数调用检索；`request_heartbeat=true` 用于连续调用多个函数；上下文用到约 70% 时 harness 插入 memory-pressure 警告，促使模型把信息存下来。https://arxiv.org/abs/2310.08560 。Letta 现在改用 MemFS，并提供 `/remember` 命令和 dreaming（后台子 agent，在 N 步之后或上下文压缩时运行）。https://docs.letta.com/guides/agents/architectures/sleeptime
- **LangMem**：明确区分两种写入。hot path：agent 调 `manage_memory` 工具，工具描述默认写着 “Proactively call this tool when you: 1. Identify a new USER preference…”。background：对话结束或空闲后由 LLM 反思抽取，召回率更高。https://langchain-ai.github.io/langmem/concepts/conceptual_guide/ ，https://github.com/langchain-ai/langmem/blob/main/src/langmem/knowledge/tools.py
- **Zep/Graphiti**：每个 episode 摄入时，用 LLM 抽取实体和事实，再做消解；发现矛盾的边就设为 `t_invalid` 使其失效（不删除）。读取方面，论文描述的是 search API（cosine + BM25 + BFS → rerank → 拼成 context string），由开发者调用。https://arxiv.org/abs/2501.13956
- **A-MEM**：每条新记忆写入时，自动生成 note、做 link generation，并演化更新邻近的旧记忆；每轮按 embedding 检索 top-k。https://arxiv.org/abs/2502.12110
- **Windsurf/Cascade（现 Devin Desktop）**：Cascade 遇到它“认为有用”的内容会自动生成记忆，用户也可以说“create a memory of…”；读取方式是“相信相关时检索”。Rules 有 always_on / model_decision / glob / manual 四种触发方式；新的 Devin Local agent 不保存记忆。https://docs.windsurf.com/windsurf/cascade/memories
- **Cursor**：当前官方文档只有 Rules（Always / Apply Intelligently / globs / manual），旧的 Memories 文档页现在跳转到首页。“2.1 起移除 Memories”的说法只见于第三方，2.1 changelog 里没有提到，**未核实**。https://cursor.com/docs/rules
- **Gemini**：Saved info 由用户在设置中添加，或在对话中说“remember…”写入；过去的聊天在用户提到相关主题或时间时引用。https://support.google.com/gemini/answer/15637730

## 2. 分类与权衡

**写入触发**
1. **用户显式命令**：`/remember`、“remember…”、“add to CLAUDE.md”、Gemini Saved info。精确度最高，但召回最低。
2. **模型在 hot path 调工具**：Claude auto memory / memory tool、MemGPT、LangMem `manage_memory`、Mem0 MCP。灵活，但增加延迟，与主任务争夺注意力，而且依赖提示词。
3. **每轮之后固定运行的抽取流水线**：Mem0 `add()`、Zep、A-MEM。召回稳定，但每轮都有 LLM 开销，噪声和重复靠去重或失效机制处理。
4. **后台 / sleep-time 整合**：Codex memories（空闲后 extract + consolidation）、Letta dreaming、LangMem background。不影响响应延迟，召回更高，但更新有延迟（Mem0 论文报告 Zep 写入后数小时检索效果才变好）。
5. **会话结束 / 压缩钩子**：Letta dreaming 可选“上下文压缩时”运行；Claude Code 压缩后重新注入根目录 CLAUDE.md；memory tool 的多会话模式建议“结束前更新 progress log”。

**读取触发**
- **始终预加载**（CLAUDE.md、AGENTS.md、MEMORY.md 索引、Letta core block）：零漏检，但占用上下文，内容多了遵循度下降（Claude 文档建议控制在 200 行以内）。
- **harness 每轮相似度检索**（A-MEM、Mem0/Zep 由开发者每轮调用 search）：可扩展，但可能检索到无关内容或漏掉。
- **模型通过工具决定是否检索**（memory tool `view`、MemGPT archival search、LangMem `search_memory`、Claude 主题文件、Windsurf model_decision）：省 token，但模型可能“忘了去查”。
- **混合**（主流做法）：始终预加载一份小索引或摘要，详细内容按需用工具读取（Claude auto memory 就是典型）。

**信号来源**
- **提示词驱动**：API memory tool 自动注入的协议、LangMem 工具描述（“Proactively call…when…”）、MemGPT 系统指令、Mem0 的抽取提示（`custom_instructions`）。
- **代码驱动**：目录层级加载规则、glob 匹配、字节或行数截断、空闲时间阈值、配额阈值、MCP / 外部上下文排除、MEMORY.md 超限时报错、上下文 70% 时的压力警告、哈希去重。

**隐私与过期**
- 隐私：Codex 会脱敏 secrets，并可排除用过 MCP 或 web 搜索的会话；Claude 文档建议在 handler 层过滤敏感信息。
- 过期：Claude 给记忆文件加 `modified` 时间戳；Mem0 v3 用 linked memory + `latest_only`；Zep 用双时间轴（bi-temporal）失效。

## 3. 对比表

| 系统 | 何时写 | 谁决定写 | 何时读 | 谁决定读 | 来源 |
|---|---|---|---|---|---|
| Claude Code CLAUDE.md | 用户编辑或明确要求时 | 用户 | 启动时；子目录在触及文件时 | 代码（层级/glob） | code.claude.com/docs/en/memory |
| Claude Code auto memory | 会话中 | 模型 | 启动时读索引，主题文件按需读 | 代码（索引）+ 模型（主题文件） | 同上 |
| Claude API memory tool | 任务进行中 | 模型（被提示词驱动） | 任务开始时 `view` | 模型（被提示词驱动） | docs.claude.com/…/memory-tool |
| Codex AGENTS.md | 用户编辑 | 用户 | 每次运行开始 | 代码 | developers.openai.com/codex/guides/agents-md |
| Codex memories | 会话空闲后在后台 | 代码触发，LLM 抽取 | 后续会话注入（方式未核实） | 代码/配置 | learn.chatgpt.com/docs/customization/memories |
| ChatGPT memory | 用户要求，或模型判断有用 | 用户/模型 | “可能有帮助时” | 系统（机制未公开） | help.openai.com/…/8590148 |
| Mem0 SDK | 开发者调用 `add()`（论文为每轮） | 代码；抽取由 LLM 完成 | 开发者调用 `search()` | 代码 | arxiv 2504.19413；docs.mem0.ai |
| Mem0 MCP | 会话中 | 模型 | 会话中 | 模型 | docs.mem0.ai/platform/mem0-mcp |
| MemGPT/Letta | 任意时刻，含压力警告时；另有 dreaming | 模型；后台子 agent | core 始终在上下文；archival 用工具读 | 模型 | arxiv 2310.08560；docs.letta.com |
| LangMem | hot path 或后台 | 模型 / 后台 LLM | 开发者预加载，或用 search 工具 | 代码/模型 | langmem 文档与 tools.py |
| Zep/Graphiti | 每个 episode 摄入时 | 代码触发，LLM 抽取 | 调用 search API 时 | 开发者代码 | arxiv 2501.13956 |
| A-MEM | 每条新记忆时 | 代码触发，LLM 建链 | 每轮 top-k | 代码 | arxiv 2502.12110 |
| Windsurf Cascade | 对话中，或用户要求时 | 模型/用户 | “认为相关时” | 模型 | docs.windsurf.com/…/memories |
| Gemini | 用户要求时 | 用户 | 用户提到主题时 / Saved info | 系统 | support.google.com/gemini/answer/15637730 |
