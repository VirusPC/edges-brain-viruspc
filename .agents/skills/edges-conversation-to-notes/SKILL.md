将原始对话整理为结构清晰的中文笔记（**同时包含记录与复盘总结**）。

- 路径在所选材料根下用 `notes/YYYY-MM-DD--主题简述/INDEX.md`（日期只在目录名）：默认材料根为 `<scope>/.edges`，选定 Project 后为 P；未选 Project 的 `--super` 为 `<scope>`。
- `--title`、正文 `#`、frontmatter `title` 只写主题简述。
- 范例一级标题写 `# 主题简述`。

术语与已定决策见同目录 [CONTEXT.md](./CONTEXT.md) 与 [docs/adr/](./docs/adr/)。

## When to Use

用户说「整理对话 / 总结这次对话 / 整理成笔记」等时：先完成本 skill 正文，再入库已选 scope 或 Project 的 Notes（私密内容写入用户指定的私密仓）。

## Inputs

- 原始对话全文（或足够完整的摘录）

## Instructions

1. 识别核心主题；一场对话多主题时可写 **总览笔记 + 各主题笔记**，在补充说明里互相链接。
2. 目录名里的日期用用户本地时区当天，除非对话明确对应另一天。
3. 全文用 Markdown 标题分层（`##` / `###` / `####`），**不要**再用【背景】等方括号栏名。**章节标题不要加括号**。
4. 正文章节顺序固定为：
   `背景 → 主题 → 过程 → 结果 → 所学 → 行动指南 → 补充说明`
5. **背景**：为何开这场、意图（不是过程流水，也不是判断升华）。
6. **主题**：先用**一段话**点明这场在学/谈/办什么；其下用列表写出**难点**（可一条或多条）。列表没有真实难点就不硬凑，主题段必有。
7. **过程**：时间线；小节标题带具体时刻或时间段；少评价。无时刻写「时刻不详」，不得改成纯主题归类。过程中真实发生的取舍**原样保留**，不要删减或压成摘要。禁止把过程同义改写塞进所学来「代替」过程。
8. **结果**：做成了什么、还剩什么、有没有回退；少讲原理。
9. **所学**：
   - **学习类对话**：知识点总结与边界判断。
   - **行动类对话**：内容优先放行动指南；所学可写边界判断与取舍补充，可极短但不要为省事删掉已有取舍。
   - **补充取舍**（不是压缩过程）：在所学里补上相关可选项、为何不做、最终认的知识与方案；过程里的轨迹仍保留。
   - 技术机制类内容须把难点说清楚（难在哪、为何难、如何处理或仍未解决），主要落在「主题」难点列表，所学可展开。
   - 不写按钮步骤，不把问题/方案堆在这里冒充行动指南。
10. **行动指南**（必须分层）：
    - **主题行动指南**（可泛化，不绑主机名/网段/脚本路径）：
      - `#### 背景`
      - `#### 核心问题`
      - `#### 核心解决方案`（编号步骤，可执行）
      - `#### 验收标准`（清单；当作以后当真任务执行时的完成判定）
    - **细节与其他**：每个点一个 `#### 若…` 小标题；正文写「则…」；复杂用列表。主机名、路径、账号、网段只出现在这一层。
    - **写「做什么 / 怎么做」时**：默认写上相关可选项，以及**为什么不做那些**。只写对话里出现过或显然相关的选项，未讨论过的不编造。步骤很短、对话里明显没有比较空间时，可省略可选项，或写「当时未比较其它方案」；不要为凑格式硬编。
    - 行动指南里的取舍是**补充**，不是把过程折短。
11. **补充说明**：琐碎信息、对照表、参考链接（每条附说明）；可链接其它 note。
    - **原始材料引用（必有）**：必须留下可追溯的出处，例如对话会话/助手、PR/commit、本地协作路径、相关 note 链接；能写时间范围更好。目的是**避免上下文丢失**——后人能回到原料核对与续写。整理不等于扔掉原料指针；脱敏后仍要能找回原件。
12. 白话完整句；禁止自创黑话、口头禅小标题、未解释的自创缩写。真实产品/协议名可保留。
13. 不在本 skill 里「升为 Edge」。
14. 输出必须为中文。
15. **入库**（正文写作与审阅完成后）：
    - 有 shell 时交给 `edges --scope <目录> notes create --title "主题简述" --body "<审阅后的 Markdown>"`；归入已有 Project 则加根参数 `--project <相对路径>`，相对 `<scope>/.edges/projects`，嵌套用 `P/projects/Q`。需要 scope 直属 Notes 且未选 Project 时才用 `--super`。不把 P 改成 scope，不代为初始化。子命令是 `notes create`。完整 Markdown 放进 `--body`。这次调用只在本地写下叶子，不 commit、不 push、不开 PR。不要自己 `git commit`，也不要传已删除的 `--content`、`--content-file`、`--markdown`、`--import-entry`、`--co-author`、`--mode`、`--dry-run`、`--format`、`--resources`、`--index-group`。
    - 无 shell 时按 `$edges` 的 [Notes reference](../edges/references/notes.md) 调用 `new_note`，传相同正文和可选 `project` / `super`；scope 由服务端确定。工具版本缺少所需选择参数时说明限制，不静默改归属。创建后保留返回 path，后续查读与更新沿用原 scope 和 Project 选择。
    - `notes create` 不复制旁路目录。图片等资源不要指望随笔记一起导入；正文里需要的材料写进 `--body`。不批量转换旧笔记。
    - 仓：普通内容写进用户自己的笔记仓（`--scope` 指向的目录）；主题归属再用 Project 选择。私密内容写入用户指定的私密仓：调用时把 `--scope` 指向私密仓的目录，`notes create` 不会自动换仓。CLI 源码在本仓 `packages/cli/`。
    - 大范围代码改动仍走 Cursor cloud agent
    - 公开库先脱敏（无 Tailscale `100.x`、凭证、授权链接等）
    - 若随后把遗留项开成看板任务，看板文件进受保护的 `main` 必须开 PR，不要直推。笔记创建本身不提交 Git。
16. **遗留项 → 任务**：若「结果」中仍有未闭环事项，整理入库后不要默默结束。默认按优先级一次挑 1～2 条，向用户逐点问清（至少能写清背景与目标），再调用 `edges-conversation-to-tasks` 成文开卡，同时传递已选 scope、Project 与笔记 path，除非任务内容另有归属；问完落库后再问下一批，避免一次烤光。用户明确说「先不转任务」则可跳过。
17. 旧笔记不强制回写。
18. 落盘前可对照 edges 项目记忆（如 `project_conversation_notes_plain_rich_human_review`）；冲突以本 skill + CONTEXT/ADR 为准。

## Output Format（压缩范例）

```markdown

> 可选：为何重要（一两句）

## 背景
...

## 主题

- 难点一：…
- 难点二：…

## 过程

### HH:MM 事件名
...（含当时真实取舍，不压缩）

## 结果
做成了什么；还剩什么。

## 所学
...（补充取舍：可选项与为何不做；最终知识与方案）

## 行动指南

### 主题行动指南

#### 背景
...

#### 核心问题
...

#### 核心解决方案
1. ...（有比较时附：相关可选项与不做原因）
2. ...

#### 验收标准
- ...
- ...

### 细节与其他

#### 若 …
则：...（有比较时附可选项与不做原因）

## 补充说明
- 原始材料：…（会话/助手、PR 或路径、时间范围）
- 链接：[其它笔记](../YYYY-MM-DD--其它主题/INDEX.md) — 说明
```

## Constraints

- 不添加原记录中不存在的新观点。
- 结构完整；某节确实无内容可写「无」。
- 禁止旧栏名：主要结论、认知更新、Facts–Insights–Actions、单独【相关链接】、方括号四栏名。
- 章节标题不加括号。
- 主题行动指南必须可泛化；验收标准必须可当任务完成判定。
- 不得用「收成/压缩」把过程里的取舍删掉；所学与行动指南只做取舍补充。
- 写做什么时默认带相关可选项与不做原因；无比较空间时可省略或写「当时未比较其它方案」，不硬编。
- 主题须有一段话；难点列表按实填写。
- 结果有未闭环项时，默认逐点问清后交 `edges-conversation-to-tasks`（一次 1～2 条）；用户说先不转任务可跳过。
- **必须保留原始材料引用**（补充说明或背景末）：会话/PR/路径/相关 note 等可追溯指针；脱敏后仍要能找回。
- 忌「记完结构」交差；人看不懂就加长改写后再入库。

## Limitations

- 依赖输入文本提供足够语境。
