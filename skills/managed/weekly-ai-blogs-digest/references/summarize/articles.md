# 精选文章

先读 `cleaned/articles/` 里的候选正文，再决定收不收，再给入选的文章写正式摘要。不能只靠标题或索引开头挑选。内部阅读笔记不是给读者的摘要，也不必给全部候选都写正式摘要。

侧重点是 Agent 与产品。研究向、红队、纯学术长文可以不写。融资、IPO、营收、定价套餐、厂商自写客户案例不收，除非其中有具体技术或产品细节。优惠和白嫖不写。判断依据是内容，不是 URL 路径。

产出 `summary/articles/{id}.json`。ID 沿用清洗阶段的文章 ID。文件里有标题、链接、一句话，以及够写时的五段：解决什么问题、如何解决、效果怎样、洞察与启发、相关工作。每段一两句。没有新的洞察就去掉那一段。没有数字就写定性结果。订阅源偏短就只留一句话，并写明订阅源里只有这些，不编长文。一句话里用一处 `mark` 标出句中已有的词，不改写成新词。

另有 `category` 和 `company`。主类只能是模型、架构、产品、实践、开源、其他。发文公司按 `site/src/lib/ai-news-category-filter.mjs` 归并。非 GitHub 链接不放进开源项目；仍值得写的留在这里。

补录若已在候选里，可以入选，日期仍是原发日，并标明补录。

候选或某篇正文变了，重写受影响的卡片，以及映射到这些 ID 的关键词。项目筛选和模型榜的变化不重写没引用它们的文章。
