# 03 并行写总结

写新周报和给已有周报补总结，都走这一步。全文只来自快照 `issues/YYYY-MM-DD/feeds.json`。不要跳过这份数据直接打开网页。

主 Agent 不把整份 JSON 读进上下文。入选文章每批 3 到 5 篇，交给子 Agent。每个子 Agent 只对自己的链接跑 `--pick`，不重新抓取：

```bash
/tmp/weekly-ai-blogs-digest-py312/bin/python scripts/fetch_feeds.py \
  --pick /path/to/ai-news-data/issues/YYYY-MM-DD/feeds.json \
  --link 'https://例子/a' --link 'https://例子/b'
```

子 Agent 按自己读到的 `summary` 写。一篇一条，不编数字。没有子 Agent 时，主 Agent 按同样的 `--pick` 逐篇读，一次只读一篇。

`summary` 就是订阅源给出的正文。偏短、只有标题或只有简介，都按这个长度写，不要把它当成缺了全文。够写五段，就写标题行、一句话和折叠的完整总结。不够写五段，只留一句话概括，并写明「订阅源里只有这些」。不要编，也不要为此打开文章页。

主 Agent 收齐后排进章节，核对链接、主类和发文公司，不再重读全文。

## 单条

「精选文章」里每条 `####` 先写主类，只能是这 6 个之一：模型、产品、Agent 与 Harness、工程实践、开源、行业。

主类后面是发文公司，不写文里讨论的产品。火山引擎的投稿在讲 Claude Code，标火山引擎。大淘宝技术、淘宝闪购、阿里技术等阿里系发文都标阿里。腾讯技术工程写腾讯。Devin 博客的 publisher 是 Cognition。Kiro 写 AWS。claude.com、claude.dev 写 Anthropic。合作新闻只标发文博客的公司。一条只标这一篇的公司。

站点「来源」一行不按文章出现顺序排。国内在前，国外在后；同一边再按大模型公司、AI 公司、传统互联网。同一档里中文按拼音，英文按字母。没写进分类表的公司排在最后。分类表在 `site/src/lib/ai-news-category-filter.mjs`。写周报时不要为了筛选顺序调整条目先后。

模型条目和项目开源不加这套主类。模型条目直接放在「二、模型进展」里，不要再写「模型发布」标题。

```md
#### &lt;Agent 与 Harness&gt;&lt;阿里&gt;[{{标题}}]({{url}})

一句话概括这篇在做什么。写这一句时就用一处 `<mark>` 包住句中已有的关键词，写进周报源稿。一句最多一处，不要整句都包，也不要改写成新词。站点构建只渲染这个标记，不在页面里挑词。

<details class="article-more">
<summary>完整总结</summary>
<p><strong>解决什么问题：</strong>一两句。</p>
<p><strong>如何解决：</strong>一两句。</p>
<p><strong>效果怎样：</strong>没有数字就写定性的结果，不编数字。</p>
<p><strong>洞察与启发：</strong>写出这一段才有的判断、观察或启发。不要复述「解决什么问题」。没有新内容就删掉这一段。不要写成操作清单。</p>
<p><strong>相关工作：</strong>点出它和这一期别的模型、产品或做法的关系。</p>
</details>
```

「项目开源」只收 GitHub 仓库：一周榜前 5，以及其他确实是 GitHub 仓库的开源项目。不标主类，不标公司。每个仓库单独一张卡，不要写成编号列表。「GitHub Trending（weekly / all 前 5）」和它下面那句概括留在卡片外面。

```md
#### [owner/repo](https://github.com/owner/repo)

一句话介绍这个仓库。关键词同样在写的时候用一处 `<mark>` 包进源稿。

<details class="article-more">
<summary>完整总结</summary>
<p><strong>解决什么问题：</strong>一两句。</p>
<p><strong>如何解决：</strong>一两句。</p>
<p><strong>效果怎样：</strong>没有数字就写定性的结果，不编数字。来源没有效果就不要写效果。</p>
<p><strong>洞察与启发：</strong>写出这一段才有的判断、观察或启发。不要复述「解决什么问题」。没有新内容就删掉这一段。不要写成操作清单。</p>
<p><strong>相关工作：</strong>点出它和这一期别的模型、产品、项目或做法的关系。</p>
</details>
```

项目卡和精选文章用同一套五段，不标主类，不标公司。依据是快照里的 trending 正文、仓库 README 或页面上能核到的事实。不够写后两段就不要硬写，并写明来源里只有这些。不够写前三段，只留一句话。

博客和其他非 GitHub 链接不放进「项目开源」。仍值得写的，放到「精选文章」，按上面的文章卡片写。

`<details>` 到 `</details>` 中间不要空行。空行会让后面的段落掉出折叠块。小标题用冒号并加粗。源稿不要自己套卡片 div。

一句话尽量短。精选文章和项目卡都按这五段写，每段一两句。项目卡信息不够时不要硬写后两段。不要把同一来源的多篇合成一条，也不要用「其他短讯」收成列表。完整总结里不要再放 markdown 链接。源稿第一段仍写「解决什么问题：」，站点显示成「什么问题」。一句话的 `<mark>` 必须随源稿入库；没有标记时站点不补划。
