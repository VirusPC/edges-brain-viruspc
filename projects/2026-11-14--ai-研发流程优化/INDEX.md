# AI 研发流程优化

这个 Project 用来持续优化 peng cheng 的整条 AI 研发流程，看每个环节的效率和质量。2026-11-14 建立。到这一天为止，这里只有一份观测。

## 目的

把任务下发、编码、审查、发布和评测连成一条可以反复测量的流程。一次观测记下当时发生了什么；一次改进只有在后续同类观测里对得上，才算生效。

## 范围

覆盖这些环节：

1. 任务下发
2. 云端编码 Agent 与本机编码 Agent
3. AI code review
4. CI
5. 合并与发布
6. 观测与评测

某一份报告通常只覆盖其中一段。没有观测的环节保持空白，不把一份报告的结论推广到整条流程。

## 怎么积累

- 每份数据报告是一次观测。正文写清来源、时区，以及观测覆盖的时间范围。
- 只写已经发生的数据，以及从这些数据可以直接读出的结论。缺的分项保持缺，不补数字。
- 改进项写成可验证的假设：写明要动什么、用哪类任务对比、什么读数算对上。在对照观测出现之前，假设只留在「后续方向」，不写成已经生效的改进。
- 本仓公开。凭据、未公开的域名和主机、项目 ID、trace ID、云端 agent ID 不入库。能点名的公开仓库和 PR 用公开链接。

## 当前已知问题

以下只来自 2026-11-14 这一次 Cursor 云端样本，时间均为 Asia/Shanghai。完整拆分见下方「观测」。

- 用户感觉每次「初始化环境」很慢。该次 Cursor UI 上的四步是 Environment ready 289 ms、Restored workspace files 401 ms、Installed dependencies 72 ms、Started agent services 154 ms，合计约 0.9 秒。
- 从第一条观测起，主 turn 墙钟 847.531 秒。工具墙钟合计 67.145 秒（7.9%），工具之间空闲 780.386 秒（92.1%）。前 5 分 54.8 秒只有 Read、Grep 和 skill，没有 Shell。
- 观测没有盖住全程。云端不触发 sessionStart / sessionEnd，UI 上的启动四步、排队、拉 VM 和环境快照不进自建 Langfuse。任务约 19:49 后发起，第一条观测在 19:51:07.183，中间约一分多钟没有分项。插件把整轮记成一条 LLM generation，没有 modelId，没有 TTFT。

本机编码 Agent、AI code review、CI 耗时、合并发布和评测跑分，这次都没有耗时数据。样本只记录了结果 PR 的 CI 有两项通过，以及观测时点该 PR 尚未合并。

## 后续方向

下面四条都是待验证的假设。本次没有对照样本。

1. 任务说明里直接点名要改的文件、入口和要跑的测试。验证：同类任务（同类仓库、同类改动规模）对比「第一条观测到第一次 Shell」的墙钟，并核对改动仍落在被点名的入口上。
2. 在仓库 AGENTS 里补更精准的入口索引。验证：与上一条分开做。只改索引、不改任务说明，再看 Agent 用于大范围 Read / Grep 找入口的时间是否下降。
3. 补齐观测：记录发起时刻，并记下单次模型调用的 modelId 与 TTFT。验证：下一次同类任务能拆出启动前等待，以及每次模型调用的耗时。
4. 用同类任务做前后对比。这是前三条的对照方法。第二份同类观测写入本 Project 之前，不宣布任何一条已经生效。
