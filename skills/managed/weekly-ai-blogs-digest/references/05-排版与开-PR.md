# 05 排版与开 PR

文件名 `ai-news/YYYY-MM-DD-ai-news.md`。说明文件同名 `.notes.md`，站点不收录。写完更新 [`ai-news/README.md`](../../../../ai-news/README.md)。榜单图和 SVG 放在同一目录，正文引用 PNG。

正文不要文首一级标题。第一行：

```
覆盖窗口：{{D-7}} 00:00:00 至 {{D-1}} 23:59:59（UTC；生成日 {{D}}，不含当天）。
```

源文件保持 UTC。站点渲染时只把含「（UTC；」的这一行加 8 小时。章节顺序：

1. 一、本周关键词
2. 二、模型进展（Artificial Analysis、LLM Arena、OpenRouter，然后直接写模型条目，不加「模型发布」标题）
3. 三、项目开源（weekly / all 前 5 的 GitHub 卡片，再写其他 GitHub 仓库）
4. 四、精选文章，下面按来源类型分「国内模型厂」「国外模型厂」「国内非模型厂」「国外非模型厂」，空的一节不写。已发布各期也按这四节排。xAI、Meta 在国外模型厂，后补的条目用这两个标签就会进这一节
5. 以后的「推特」「播客」是精选文章后面的同级章节，不写进精选文章里面

某一章没有可核对的内容就整章去掉，不留空标题。章节标题单独成行，前面留空行。不要把 `<br/>` 放进上一条的正文里。

精选文章和「项目开源」里的 GitHub 项目卡都由站点套上笔记卡。两边的完整总结都是五段：解决什么问题、如何解决、效果怎样、洞察与启发、相关工作。源稿保持 [写总结](03-并行写总结.md) 的格式，不要自己套卡片 div，也不要给项目卡加主类或公司标签。「GitHub Trending（weekly / all 前 5）」标题下面不要写概括前五名字的介绍句，例如「这期看的是一周榜，前五是……」。标题之后直接写各仓库卡片，也不要用编号列表。这些项目卡不进精选文章的标签筛选。非 GitHub 链接不放进「项目开源」。

开 PR，不合并。看板文件进 main 也走 PR。不要提交密钥、`node_modules`、抓取脚本的缓存。

链接必须在快照里真实出现。失效就修或删。不要编造 Trending 名次或榜单数字。订阅源偏短的条目只留一句话，并写明订阅源里只有这些。读者正文和图下不要写「数据取自」「快照」「抓取于」这类过程说明；覆盖窗口那一行保留。溯源放说明文件。

播客默认不逐期总结。用户要求时，或这一窗口有和 AI / Agent 强相关的一期时，只在关键词或相关章节点名一句并附链接。不要把播客加进 OPML。
