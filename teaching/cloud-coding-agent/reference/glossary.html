术语表

这门课的“统一说法”。之后每一课都只用这里的词；同一个东西不换着叫。

规则：产品名和这几个词保持英文——Agent、CLI、MCP、Sandbox、AI Gateway、PR、Keep Alive。其他尽量用平常的中文。定义只说“它是什么”，一两句话。随着你理解加深，定义会被修改，而不是另起一条。

整体

云端编程 Agent 平台
一种产品：用户在网页上提一个改代码的需求，平台在云上的隔离机器里让 Agent 改代码，最后交回一个分支或 PR。本课研究的 coding-agent-template 就是一个例子。 后台代理、远程 Copilot
任务Task
用户提交的一次需求，以及它从开始到结束的全部记录；在数据库里就是 tasks 表的一行。 schema.ts L76–114作业、job、工单
Agent
真正读代码、改代码的 AI 程序。在本项目里，Agent 就是各家现成的 CLI，平台自己不写 Agent 逻辑。 机器人、bot、智能体
Agent CLI
以命令行方式运行的 Agent，例如 Claude Code、Codex CLI、Cursor CLI、Gemini CLI、GitHub Copilot CLI、opencode。 lib/sandbox/agents/index.ts L12插件、脚本
免确认模式
让 Agent CLI 不再逐条询问“可以执行吗”，直接动手的运行方式，如 --dangerously-skip-permissions。只有在 Sandbox 里才敢这样用。 lib/sandbox/agents/claude.ts L278自动模式、yolo（除非引用原参数名）

运行环境

SandboxVercel Sandbox
为一个任务临时开的隔离 Linux 虚拟机，有自己独立的系统内核和文件系统，到时间会自己停。底下是一台 Firecracker microVM，不是 Docker 容器（第 3 课）。 Vercel 文档容器、沙盒、沙箱环境、VM（泛指时可以说“虚拟机”）
最长时长maxDuration
用户给 Sandbox 设定的存活时间上限，单位是分钟；本项目的选项是 5 分钟到 5 小时，建 Sandbox 时换算成毫秒传给 timeout，时间一到 Sandbox 自动停。注意它和下面的“函数时长上限”是两回事。 components/task-form.tsx L724–L733 lib/sandbox/creation.ts L73–L75超时、TTL
Keep Alive
一个开关：任务结束后是否留着 Sandbox，好让用户继续追问。打开时留到最长时长用完；关闭时只结束机器里的进程，机器本身照样开到超时（README 说“立刻关掉”，代码并非如此）。 app/api/tasks/route.ts L668–L683 lib/sandbox/git.ts L75–L100保活、常驻
项目目录PROJECT_DIR
仓库在 Sandbox 里的存放位置，固定是 /vercel/sandbox/project。 lib/sandbox/commands.ts L4工作区、workspace

Sandbox 的一生

空转
本课自己起的说法：Keep Alive 关闭时，任务结束后进程被结束、但机器还开着，一直等到最长时长用完的那段状态。 lib/sandbox/git.ts L75–L100待机、休眠（这两个词容易让人以为不花钱）
重连Sandbox.get()
拿着之前存下的编号（本项目是数据库里的 sandboxId，新版 SDK 改用名字）重新连上一台已有的 Sandbox。 app/api/tasks/[taskId]/continue/route.ts L169–L190恢复连接、re-attach
停止stop()
主动让 Sandbox 关机的方法。本项目只有“停止 Sandbox”接口和内存登记表会调用它。 app/api/tasks/[taskId]/stop-sandbox/route.ts L35–L57销毁、删除（新版 SDK 里删除是另一个方法 delete()）
冷启动
从零开一台新 Sandbox、拉代码、装依赖的那段等待时间。重连或从快照开机可以省掉其中一部分。 启动延迟、预热
会话session
新版 Vercel Sandbox 里，一台 Sandbox 的一次开机运行。一台 Sandbox 可以有很多个会话，最长时长管的是单个会话。 Vercel 文档实例、一次 run
快照 / 模板snapshot · template
把一台机器“装好之后”的文件系统（有的平台连运行中的进程也一起）存下来，以后直接从它开机，跳过安装。Vercel 叫快照，默认最后一次使用后 30 天过期；E2B 叫模板，构建时就拍好。它是“跑出来的结果”，会随依赖和代码变化而过时。 Vercel 文档 E2B 文档备份；也不要和“镜像”混用（镜像是按 Dockerfile 建出来的，快照是从跑着的机器拍下来的）
持久化persistent
新版 Vercel Sandbox 的默认行为：停下时自动拍快照，下次有命令进来时自动从快照开机。本项目用的旧 SDK 没有这个能力。 Vercel 文档常驻、保活（那是 Keep Alive）
函数时长上限Vercel Function maxDuration
Vercel 给一次服务器函数调用设的最长运行时间，单位是秒；after() 里的后台流程也受它约束。本项目在 vercel.json 里给任务接口设了 300 秒。 vercel.json L1–L8 Vercel 文档超时时间（会和最长时长混淆）

预制环境与隔离（第 3 课）

镜像image
一台机器开机时的“初始文件系统”：操作系统、系统包、语言工具，通常用 Dockerfile 描述、构建出来。Vercel Sandbox 用 Sandbox.create({ image }) 指定，不指定时用官方的 vercel/sandbox/universal。 Vercel 文档快照（那是从跑着的机器拍下来的）、模板
OCI 镜像OCI image
Docker 镜像所遵循的开放标准格式：一叠文件系统层，加一份配置（里面有 Entrypoint、Cmd 等）。Vercel 只拿文件系统层当 microVM 的根文件系统，不执行配置里的启动命令。 OCI Image Spec“Docker 格式”（可以理解，但统一说 OCI 镜像）
VCRVercel Container Registry
Vercel 自己的镜像仓库，按项目划分。用 vercel vcr build 构建并推送，Sandbox 只能用其中准备好的 linux/amd64 镜像。 Vercel 文档Docker Hub（那是另一家的仓库）
setup 脚本setup / install script
在 Agent 开工之前、按仓库跑的准备命令：克隆、装依赖、生成代码。可以联网，私有仓库的密钥只应在这一步出现。Codex 叫 setup script，Cursor 叫 install，Copilot 是 copilot-setup-steps.yml。 Codex 文档初始化、启动脚本（启动脚本是开机后起服务用的，另一回事）
maintenance 脚本maintenance script
Codex Cloud 的概念：从缓存好的环境恢复时，可选地再跑一次的补差命令，用来处理“setup 是在旧提交上跑的、依赖需要更新”的情况。 Codex 文档维护任务、定时任务
prebuild
GitHub Codespaces 的概念：提前跑完 dev container 的创建命令、拍下容器快照存起来，新开 codespace 时直接用；默认每次 push 自动重建。泛指“提前做好环境”时，本课说“预制环境”。 GitHub 文档预编译、预构建（容易和编译代码混淆）
内核kernel
操作系统最底层的那部分程序，管内存、进程、文件和网络，所有程序都要通过它才能碰硬件。隔离强不强，关键看几台机器是不是共用一个内核。 系统、底层（太泛）
容器container
和宿主机共用同一个内核、靠内核的 namespaces 和 cgroups 隔开的一组进程。启动快、开销小，适合跑自己信得过的代码。 Docker 文档把 Sandbox 叫成容器；“轻量虚拟机”
microVM
只保留最少设备、启动很快的小型虚拟机。每台有自己的内核，靠硬件虚拟化和宿主机隔开，比容器多一份内核的开销，换来更强的隔离。 Vercel 文档微型容器、轻量容器
Firecracker
AWS 开源的 microVM 软件，最初为 AWS Lambda 而做；基于 Linux 的 KVM，只模拟 5 种设备，官网写启动不到 125 毫秒。Vercel Sandbox 和 E2B 都用它。 Firecracker 官网Docker 的一种、容器运行时

Agent CLI 适配层（第 4 课）

适配层adapter layer
平台和各家 Agent CLI 之间那层“翻译”代码：把统一的任务（提示词、模型、密钥、MCP 配置）翻成某一家 CLI 认得的命令行参数和配置文件，再把它的输出翻回平台的日志和会话编号。模板里入口是 executeAgentInSandbox，按 agent 名分发到 6 个文件，没有共同的接口类型。 index.ts驱动、插件（模板里不是插件机制，是一个 switch）
无确认模式auto-approve / yolo mode
让 CLI 执行命令、改文件时不再停下来问人的开关，例如 Claude 的 --dangerously-skip-permissions、Gemini 的 --yolo（新版写成 --approval-mode=yolo）。云端无人值守必须开，于是安全只能靠外面的 Sandbox。 Claude Code 文档“安全模式”（正好相反）
stream-json
CLI 把运行过程按“每行一个 JSON 对象”实时吐出来的输出格式。平台逐行解析，就能把工具调用、最终结果和会话编号转成网页上的进度。注意数据按块到达，一行可能被切成两块。 Claude Code 文档JSON 输出（那通常是结束时一次性给出的一个对象）
会话编号session id / resume
CLI 为一次对话分配的标识。下次带上它（如 --resume），CLI 能接着上次的上下文继续。模板把它存进 tasks 表的 agentSessionId；Copilot 声明了却从没赋值，Gemini 没有续聊。 copilot.ts L202任务编号（那是平台自己的 id）
提示词转义prompt escaping
把用户写的提示词安全地塞进一条 shell 命令里。模板去掉 $ 和 \、把反引号换成单引号，再放进双引号里交给 sh -c，但没处理双引号本身；Copilot 和 Cursor 用参数数组传，绕开了这个问题。提示词注入（那是指让模型听从恶意内容，另一回事）
提示词注入prompt injection
仓库文件、网页、issue 里藏着的文字被模型当成命令执行，例如“把环境变量发到某个网址”。CLI 开着无确认模式、Sandbox 能联网、密钥又在里面时，这是最现实的风险。 OWASP LLM Top 10越狱（jailbreak 是针对模型自身规则的）
网络策略network policy
Vercel Sandbox 控制出网的设置：默认 allow-all，可改成 deny-all 或按域名放行，运行中也能改。按 TLS 的 SNI 匹配域名。 Vercel 文档防火墙规则（可以这么理解，但它只管出网）
凭证注入credentials brokering
密钥不放进 Sandbox，而是由 Sandbox 外面的出网代理在请求发往某个域名时，替它加上带密钥的请求头。Agent 读不到真密钥，也就偷不走。Vercel 2026-02-23 上线，用网络策略里的 transform 配置。 Vercel changelog密钥托管、环境变量（那正是要避免的）
脱敏redaction
写日志前把密钥、令牌等敏感字符串遮掉。模板用一组正则做，保留前 4 位和后 4 位；OpenAI 那条正则把 sk- 误写成字符类 [sk-]。 logging.ts L11–L16加密（脱敏后原文就丢了，不能还原）

进度链路与任务状态（第 5 课）

轮询polling
浏览器每隔固定时间主动问一次服务器“有没有新东西”。模板用三个 setInterval：任务详情 5 秒、消息 3 秒、侧边栏 5 秒，任务结束后也不停。 use-task.ts长轮询（long polling 是服务器把请求挂住、有新数据才回）
NDJSONnewline-delimited JSON
每行一个 JSON 对象的文本格式，适合边产生边传输。Sandbox SDK 读命令输出的接口 /cmd/{id}/logs 返回的就是 application/x-ndjson。SDK 0.0.21stream-json（那是 CLI 自己的输出格式，碰巧也是一行一个 JSON）
SSEServer-Sent Events
浏览器用普通 HTTP 打开一条长连接，服务器单向往下推 event / data 文本。每条事件可带 id，断线后浏览器自动带 Last-Event-ID 重连。Cursor Cloud Agents API 的进度流就是 SSE。 MDNWebSocket（那是双向的、另一套协议）
WebSocket
浏览器和服务器之间的双向长连接。Vercel Functions 2026-06-22 起公测支持，但连接固定在一个函数实例上，函数到最长时长就会断，客户端要自己重连。 Vercel 文档把它当成“存进度的地方”（它只负责传，不负责存）
读改写read-modify-write
先读出旧值、在程序里改、再整体写回。两个写入者同时这样做，后写的会盖掉先写的，叫“丢失更新”。模板的 TaskLogger 每追加一条日志都这么做。 task-logger.ts追加（真正的追加是让数据库自己在末尾加，不经过程序）
写放大write amplification
为了写一点点新数据，实际写了多得多的数据。把日志存成一整列数组、每次追加都整列重写，写 N 条日志总共要搬运约 N²/2 条。写入量大（写放大说的是“比例”，不是总量）
游标cursor
增量拉取时客户端记住的“我已经看到哪儿了”，通常是事件的自增序号。下次请求带上它，服务器只返回之后的新事件。数据库游标（同名，但那是逐行读取结果集的机制）
状态机state machine
一个对象只能处在有限几种状态之一，并且只能按规定的路线在状态之间变化。模板的任务有五种状态（pending / processing / completed / error / stopped），但写状态时不检查“从哪来”，终态可以被覆盖。 schema.ts状态字段（有字段不等于有状态机）

密钥与信任边界（第 6 课）

信任边界trust boundary
系统里“这边的东西互相信任、那边的要当作可能被攻破”的分界线。模板里最关键的一条在服务器和 Sandbox 之间：Agent 在 Sandbox 里免确认运行、可能被提示词注入，可 GitHub 令牌、模型 key、MCP secret 都被送了进去。 creation.ts L121–L127防火墙（防火墙是守边界的一种手段，不是边界本身）
静态加密encryption at rest
秘密存进数据库前先加密。模板用 AES-256-CBC、随机 IV、全站一把 ENCRYPTION_KEY，没有完整性校验和密钥版本号；README 写的“per-user encryption”与代码不符。 crypto.ts L3–L35哈希（哈希不能解回原文，令牌必须能解回来用）
JWE 会话JWE session cookie
把会话内容（登录方式、用户信息）用共享密钥 JWE_SECRET 加密后整个放进 cookie，服务器不存会话表。cookie 一年有效；拿到 JWE_SECRET 就能伪造任意用户，服务器也没法单独踢某个人下线。 jwe/encrypt.ts L12–L15 session/create.ts L49–L66JWT（JWT 通常只签名不加密，内容可读）
OAuth 授权范围OAuth scope
用户登录时同意给应用的权限。模板申请 repo,read:user,user:email，其中 repo 是对所有公开和私有仓库的完全访问。OAuth app 的令牌默认不过期，一年不用才会被 GitHub 吊销。 signin/github L59–L64 GitHub 文档角色、权限组（scope 只是令牌上的一串标签）
GitHub App 安装令牌installation access token
GitHub App 为某次安装签发的短期令牌：可以只限定几个仓库和几项权限，一小时后过期。云端 Agent 想给 Sandbox 一把“够用但不多”的令牌时，这是现在的标准答案。 GitHub 文档个人访问令牌（PAT 绑定的是人，不是应用）
平台密钥platform key / fallback key
部署者填在服务器环境变量里的密钥。分两类：ENCRYPTION_KEY、JWE_SECRET、SANDBOX_VERCEL_TOKEN 只在服务器用；AI_GATEWAY_API_KEY 等模型密钥在用户没存自己的 key 时会兜底进 Sandbox，于是任何用户都能通过终端接口读到（推断）。 README.md L240–L246系统密钥（太笼统，分不清进不进 Sandbox）
凭据代理credentials brokering
秘密不进 Sandbox，而是由 Sandbox 外面的防火墙在出站请求上注入请求头。Vercel Sandbox 的 networkPolicy 用 transform 实现；按 SNI 匹配域名，按 IP 段放行的流量不做注入。 Vercel 文档密钥管理服务（那是存密钥的地方，不管出站请求）
环境变量串用process.env cross-talk
模板把每个用户的 key 临时写进进程共用的 process.env、跑完再恢复。Vercel Fluid compute 下多个调用共享一个实例，两个任务交错恢复，可能让前一个用户的 key 留在进程里给别人用（推断）。原值为 undefined 时恢复还会写成字符串 "undefined"。 index.ts L56–L75 L149–L158内存泄漏（这里漏的是数据，不是内存）
批量赋值mass assignment
接口把客户端请求体整个交给数据模型，让客户端能写本该由服务器决定的字段。模板创建任务时客户端可以填 sandboxId、maxDuration、prUrl 等。 tasks/route.ts L71–L82 schema.ts L117–L147SQL 注入（字段值是正常写进去的，没有拼 SQL）
归属检查ownership check
每个按编号访问资源的接口，都要确认“这个资源属于当前登录的人”，否则就是越权访问（IDOR）。app/api/tasks/[taskId]/ 下 31 个路由全部做了，其中 4 个没排除已删除任务。 terminal/route.ts L26–L31认证（认证回答“你是谁”，归属检查回答“这是不是你的”）
速率限制rate limit
限制一个用户在一段时间内能发多少请求。模板按“今天的任务数 + 用户消息数 ≤ 5”计算：新任务算两次、删掉的不算、先查后插不是原子操作，终端等接口不限。 rate-limit.ts L21–L43配额计费（这里不计钱，只计次数）
