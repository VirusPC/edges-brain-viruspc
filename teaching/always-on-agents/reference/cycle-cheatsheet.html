循环速查

一页纸看完睡醒循环、五个原语和关键实践。打印或存在手机上，合上原文前扫一遍。

一句话

always-on 只是用户体验。Agent 大半时间在睡；每次醒来是一次 run，发生在一份 session 里。事件进 inbox，worker 开 run，读 memory、在 permissions 内行动、再更新 memory，必要时把结果交给 outbox。循环一直转，才显得它一直在。

run 和 session

run：收到事件 → 做完活 → 把这次发生的事存下来 → 睡回去。

session：消息和工具调用的 transcript。用户答复这类「接着先前工作」的事件续上已有 session，其余通常新开一份。

一次 run 怎么结束

  • 把一条消息推进 outbox；
  • 判断这次什么也不必送；
  • 用 deferred tool call 请人批准或补一句。

五个原语

原语是什么挡住什么 / 原文给它的位置怎么协作
event inbox 耐用的事件列表 + handler 写入 + worker 读取 来源直接叫 Agent 时：同时到达会争出两次 run；崩溃会把事件弄丢 所有来源（含到期的 timer、用户答复）都先写进来，再由唯一的 worker 开 run
timers 独立存储里的 follow-up 或 schedule；scheduler 到期才开火 让 Agent 能主动醒来；未到期的事不进 inbox（inbox 只放已经能做的） scheduler 更新 timer 后，把事件写入 inbox 并叫醒 worker。timer 自己不开 run
memory 独立耐用存储，常是映射到数据库或对象存储的文件目录，比 worker 活得更久 多次互不相连的 run 对不上连续性；不该把外部系统里查得到的东西再存一份 run 开头读取作为基线，结束前写入新学到的。只存查不回来的东西，否则存指针
permissions 每次工具调用：自己继续、拦住，或等人批准 无人值守却握着用户的访问权：凭证进了 Agent 环境，或危险动作没人拦 凭证走环境外的 credential proxy；较高风险动作可用 auto mode 的 classifier；要人拍板时用 deferred tool call
outbox 待发消息表 + dispatcher（可选；多数情况一个 send 工具就够） 需要控制节奏或从投递错误里恢复；发太多会吵，发太少会漏掉用户该知道的事 run 结束后把行推进去，dispatcher 决定交哪些。先偏安静，再用 evals 找到平衡

关键实践（原文）

event inbox

  • handler 很快确认收到；提示词注入这类深检查放到 run 里做。
  • inbox 是真相来源：worker 醒来先拉最新待办。中途死了，新 worker 可以拿同一事件重试。
  • 同一时间只有一个在工作的 worker。
  • 中途又来事件：推到下一次 run、并进当前 run，或打断重来（原文未推荐哪一种）。
  • 把积压的待办事件批次合并，例如连续几条用户消息合成一次 run。
  • 建议先一人一个 inbox；要更多并行再拆。

timers

  • 和 inbox 分库存：inbox 只放已经能做的事件。
  • scheduler 每轮：扫描到期的 → follow-up 标完成 / schedule 改到下一回 → 写入 inbox 并叫醒 worker。

memory 四类

  • user instructions：单独文件，每次 run 开头都加载。
  • user notes：角色、偏好、纠正；变多后拆文件，开头只加载索引。
  • past messages：避免重复已经对用户说过的话。
  • task progress：每个进行中的任务一份进度，新 run 接着上次。

新 session 只有 context overhead（system prompt、工具定义、memory 文件）加上触发事件；已有 session 还带回先前的消息和工具调用。session 太长就 compact 或新开——两种都会丢细节，所以途中要把该留的写入 memory。开头保持精瘦，并用 prompt caching。

deferred tool call 往返

  1. 这次 run 结束，session 保存在调用做到一半的地方。
  2. 请求交给用户（例如一张可交互的卡片）。
  3. 答复作为事件回到 inbox。
  4. 新的 run 接着原来的 session，带上用户的输入。

等待期间，worker 仍可拾起别的事件，Agent 不会被堵住。

60 秒骨架

always-on 是体验，不是进程一直醒着。一次 run：inbox 里的事件叫醒唯一的 worker，在新的或已有的 session 里读 memory、在 permissions 内行动、再更新 memory，然后可能写入 outbox。timer 到期也是先变成 inbox 里的事件。要人批准时，结束这次 run 并保存 session，等答复作为新事件再续上。每次 run 都很短，循环可以一直转。
