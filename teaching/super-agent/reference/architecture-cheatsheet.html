架构速查

一页纸收拢第 2 至第 8 节的机制、实验限度和开放问题。适合在第 5 课之后使用。

一条事件怎么走

  1. 环境事件作为 Trigger 进入，先经程序层策略（Fast Path）再经语义层策略（Slow Path）过滤。
  2. 尚未订阅的新事件由 Router 层冷启动：创建 Worker，并让它订阅对应 Thread。
  3. 同一 Thread 的后续事件由程序直通已订阅的 Worker。订阅是多对多的。Router 仍可观测全部事件，但只分派未订阅的新事件。
  4. 向模型注入上下文时，把窗口当作 Cache：从 ID 和摘要开始，按局部性 Inline，超出则 Spill。需要时沿引用图做链式召回。
  5. 可以投机执行：后台先尝试，有价值就交付，没有就丢弃；不需要时保持安静。
  6. Worker 不直接对用户说话。Router 按信道习惯回复：IM 低打扰、单次不超过 100 词；GitHub、邮件、文档侧重结构化交付。异步 start() / stop() 让前台不必等后台工具完成。
  7. 计算在云端无状态运行，状态在数据库，执行环境留在原地，经不保存会话状态的 daemon 按需接入。Watchdog 在主系统外定期检查基础设施和任务进展。

各节关键约束

双层架构

  • 同一个 Session 最连续，但吞吐受单个 ReAct Loop 串行限制；每条事件都新开 Session 则吞吐高，却容易割裂、回复混乱。
  • Router 不执行具体任务；Worker 不对用户直说。
  • Session 是实现细节，不应成为用户的认知负担。

计算 / 状态 / 环境

  • 不要把这三件事绑在同一台设备上。
  • 云端重建沙箱或强迫用户迁云，都不是原文推荐的主路径。
  • 与 Anthropic「脑手分离」一致，但场景不同：这里首先接可能间歇在线的个人机器，支持 BYOM。

Watchdog

  • 放在主系统之外，用定时消息驱动。
  • 既看基础设施，也看任务进展。
  • 可以询问，也可以在线修正主系统（增删提示词、调整触发规则）。

实验限度（第 7 节）

  • 合成负载、简化环境，结果只作初步参考；测的是调度与协作，不是单任务编码。
  • Super-agent：p50 12.4 分钟，p95 15.7 分钟。中性提示的单 Session + Subagent：五次都未调用 Subagent，p95 29.5 分钟。
  • 去掉直通：完成时间基本一致；Router 决定约增 30%，读缓存 token 约增 37%。直通在该负载下主要省开销，不是提速。
  • 批处理：到达加快时，单个决定分摊的推理时间可以下降。

开放问题（第 8 节，保持开放）

  • 如何扩展双层架构（切分、Worker 直连、长程记忆）。
  • 脱离 Session 之后如何呈现任务、如何中途协作。
  • 如何划分上下文边界，以及不特指某协议的 A2A。
  • 如何保障安全与隐私：解决不好，就只能在很小且可信的范围工作。不要把这一条写成已经完成。
