可验证的成功：四个原子

先学会把「agent 说成功了」和「环境里真的成功了」分开。这是一切 agent 评测的地基。

主文献：Anthropic · Demystifying evals for AI agents · 2026-01-09

术语速查 第 2 课 → 原文

这一课你要带走什么

结束时，你应能用自己的话区分四个词，并给任意 agent 任务写出可在环境里核对的成功标准——而不是只听它口头汇报。

四个词，一次说清

task 任务
一条测试：有定义好的输入，以及清晰的成功标准。
trial 试次
对同一 task 跑一次。模型有随机性，所以常跑多次 trial。
transcript 轨迹
这一次 trial 里说了什么、调了哪些工具、中间发生了什么。也叫 trace / trajectory。
outcome 结果状态
trial 结束时，环境里留下的最终状态——数据库行、文件内容、测试是否通过——不是嘴上那句「好了」。
记住这一句 订票 agent 在对话末尾说「Your flight has been booked」——那是 transcript 里的话；真正的 outcome 是环境 SQL 里有没有那条 reservation。

例子 A：订票（看 outcome）

同一 task，一次 trial

  1. task：按政策帮用户改签到指定航班；成功 = 预订表出现正确新航班，且旧段按规则处理。
  2. trial：让 agent 完整跑完这一次对话与工具调用。
  3. transcript：用户话轮、政策查询、改签 API 调用、agent 的确认话术。
  4. outcome：库里的 reservation 记录是否等于标注的目标状态。

若 transcript 里客服腔调完美，但库里没有改签成功——按可验证标准，这次 trial 失败。

例子 B：改文件（coding 同理）

修「空密码可登录」漏洞

  1. task：修复空密码绕过；成功 = 相关失败测试转绿，且既有测试不挂。
  2. trial：agent 在干净仓库里改代码并跑测，算一次。
  3. transcript：读文件、编辑、跑测命令、推理过程。
  4. outcome：测试结果与仓库最终状态（必要时含安全日志事件）。

Agent 在 transcript 里宣称「已加固」，但测试仍红——outcome 说了算。

技能：写出可验证的成功

好的成功标准，应让两名领域专家独立给出同一 pass/fail。写的时候问自己：

  • 我要核对的是哪一个环境事实（行、文件、测试、票据状态）？
  • 只听 transcript，会不会被「说得对」骗过？
  • 合法的不同路径，会不会被我误判失败？（通常应评 outcome，少绑死路径。）
