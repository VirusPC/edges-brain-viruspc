# grok-bot 工作盘清理

多个助手共用 grok-bot 时，任务工作区和一次性仓库副本很容易把工作盘占满。清理前先判断，不要猜。

## 先分清三类

- **git worktree**：用各主仓的 `git worktree list --porcelain` 汇总，常见位置是仓内 `.worktrees/`、`/workspace/worktrees/`，以及散落的 `wt-*` 目录。`.git` 是文件（指向主仓）。
- **独立克隆或一次性目录**：自己有 `.git` 目录，或里面又嵌了完整仓副本，体积常接近一份完整仓。不能当 worktree 删。
- **主仓**：正在使用的仓库本身，不要删。

某个仓看起来异常大时，先拆开 `.git`、正文内容、以及被忽略的 `.worktrees/`。往往是后者堆着很多没删的工作副本。

## 扫描

1. 看 grok-bot 工作盘的 `df -h`（路径是 `/workspace`）。
2. 对每个主仓跑 `git worktree list --porcelain`，并 `git worktree prune --dry-run` 看已失效的登记。
3. 用 `du` 看大目录，区分上述三类。
4. 查有没有进程的工作目录落在这些路径里（包括网站预览、守护进程）。

## worktree：什么算「不用」

必须同时满足才能删：

1. `git status --porcelain` 为空。除构建产物外，未跟踪文件也算有改动。
2. 提交已在远端（某个 `origin` 分支能拿到，或对应的合并请求已合入／已关闭，且与该提交一致）。分离头部也要能在远端找到。
3. 近 2 小时内目录里没有人改过文件（排除 `.git`）。
4. 没有进程的工作目录或打开的文件落在这里。
5. 没有被锁定。

任一条不满足就留下，并记下原因。

删的时候用 `git worktree remove <路径>`。不要一上来加 `--force`。若只因为子模块没检出、或工作区缺少构建产物而失败，核对正文的 gitlink 没变之后，才可以加 `--force`。最后对各主仓跑 `git worktree prune`。不要删分支，不要删主仓。

## 独立克隆和一次性目录

先看用途、最近修改、是否有进程、是否有未推送的提交、是否还有人在用。没有用户明确说可以删，只列建议，动都不要动。

就算用户说「把确定没用的删掉」，也要留下：

- 主仓、工作区仓
- 近几小时还有人在用的（网站预览、评审材料、还没做完的任务）
- 有未提交的笔记或改动的
- 和远端有分叉、又不能确认这些提交已经在远端的

删之前再确认 `.git` 是独立仓的目录，而不是指向别处主仓的 worktree 文件。是 worktree 就按上一节处理，不要直接 `rm`。

## 例程里怎么用

定时检查只扫描、分类和汇报，**不要自动删**。只有用户当次明确说可以删时，才按上面的安全条件删。

## 汇报

说清楚：删了哪些（路径、分支、大小）、留了哪些及原因、清理前后的可用空间。对不能当 worktree 删的大目录，只给建议、不主动删。
