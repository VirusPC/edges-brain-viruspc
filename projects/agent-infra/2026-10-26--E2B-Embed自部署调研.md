## 1. Embed 是什么

- **定位**：把 E2B Runtime 与 Dashboard **打包到一台你控制的机器**上运行；与 E2B Cloud、E2B Bring Your Own Cloud（BYOC）并列。面向「客户数据必须留在客户环境」（政府 / 金融 / 医疗等）的交付场景。  
  来源：[introducing-e2b-embed](https://e2b.dev/resources/introducing-e2b-embed)、[embed/README.md](https://github.com/e2b-dev/runtime/blob/main/embed/README.md)
- **隔离模型**：每个 sandbox 是 **Firecracker microVM**，与 Cloud 同款 VM 隔离。  
  来源：[introducing-e2b-embed](https://e2b.dev/resources/introducing-e2b-embed)
- **SDK / API**：同一套 Python / JS SDK；迁自 Cloud 主要是换本安装的 **team API key + SDK URLs**。  
  来源：[introducing-e2b-embed](https://e2b.dev/resources/introducing-e2b-embed)、[docs.e2b.dev/byoc](https://docs.e2b.dev/byoc)
- **许可**：Apache-2.0；**不需要** E2B 账号或 license key。  
  来源：[introducing-e2b-embed](https://e2b.dev/resources/introducing-e2b-embed)、[e2b.dev/open-source](https://e2b.dev/open-source)
- **规模边界**：Embed **按设计就是单机**；要跨机扩展或由 E2B 代运维云账号内集群 → 看 BYOC / Cloud。  
  来源：[introducing-e2b-embed](https://e2b.dev/resources/introducing-e2b-embed)、[docs.e2b.dev/byoc](https://docs.e2b.dev/byoc)

四种安装形态跑的是同一套单机栈：

| 方式 | 你需要什么 | 安装命令 |
|---|---|---|
| Docker Compose | 带 KVM 的 Linux 主机 | `docker compose up -d --wait` |
| Terraform on GCP / AWS / Azure | 对应云账号与凭证 | `terraform init && terraform apply` |
| Kubernetes | 集群里一台已准备好 KVM 的节点 | `kubectl apply -k` |

来源：[introducing-e2b-embed](https://e2b.dev/resources/introducing-e2b-embed)、[embed/README.md](https://github.com/e2b-dev/runtime/blob/main/embed/README.md)

## 2. 主机要求（Compose 路径）

均摘自 [embed/compose/README.md · Requirements](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/compose/README.md)：

| 项 | 要求 |
|---|---|
| 架构 / 虚拟化 | Linux **x86-64 或 arm64**，需 **KVM**；内核页大小 **4 KiB**（Ubuntu 默认）。裸机，或开启嵌套虚拟化的 VM（GCE `--enable-nested-virtualization`；EC2 NestedVirtualization；Apple silicon 需 M3+ / macOS 15+ 的嵌套 VM） |
| 推荐发行版 | **Ubuntu 24.04**：内核 ≥ 6.8（**arm64 恢复 sandbox 需 ≥ 6.10**，否则 `Failed to UFFD object`；Ubuntu 24.04 原装 6.8 需装 `linux-generic-hwe-24.04`）、glibc ≥ 2.34、**cgroup v2** |
| 设备节点 | `/dev/kvm` 与 `/dev/net/tun` 必须存在；缺任一则停在 `preflight` 并打出 `FIX:` |
| 软件包 | `iptables`、`rsync`、`e2fsprogs`、`iproute2`；试 SDK 还需 `python3-venv`：`sudo apt-get update && sudo apt-get install -y iptables rsync e2fsprogs iproute2 python3-venv` |
| Docker | **Docker Engine ≥ 27**，**Compose ≥ 2.24**；用户在 `docker` 组。示例：`curl -fsSL https://get.docker.com \| sh && sudo usermod -aG docker $USER`（再重新登录） |
| 内存 / 磁盘 | **推荐 12 GiB RAM**、**20 GiB 空闲磁盘**。默认 `HUGEPAGES=2048` → 为 sandbox **预留约 4 GiB**（2048 × 2 MiB）；`preflight` **不检查 RAM**，内存不够时多在 `host-setup` 报 `FIX: give the host more memory … or lower HUGEPAGES` |
| 出口网络 | 出站 HTTPS 到 Docker Hub、`us-docker.pkg.dev`、`storage.googleapis.com`、`github.com`、`raw.githubusercontent.com`（镜像与产物均公开，无需账号） |

官方明确：**dedicated Linux host**；「One stack per host; there are no VM-name or port knobs。」  
来源：[compose/README.md](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/compose/README.md)、[introducing-e2b-embed](https://e2b.dev/resources/introducing-e2b-embed)

### `host-setup` 会改主机什么

每次 `up`，`host-setup` 会（摘自 compose README）：

- 加载内核模块：`nbd`（`nbds_max=NBDS_MAX`）、`tun`、`kvm`
- 写入 `/etc/modules-load.d/e2b.conf`、`/etc/modprobe.d/e2b-nbd.conf`、`/etc/udev/rules.d/97-nbd-device.rules`、`/etc/sysctl.d/90-e2b.conf`（并提高 `net.ipv4.tcp_max_syn_backlog`、`vm.max_map_count`）
- 增加一条 iptables mangle **TCP MSS clamp**
- **预留 hugepages**
- 创建 `/var/lib/e2b`、`/fc-*`、`/orchestrator`、`/var/run/netns`

`host-teardown`（`--profile purge`）可撤销上述多数变更；`kvm`/`tun` 故意保留加载。重启后需再跑一次 `up`，因 MSS clamp 与 `/var/run/netns` 不跨重启持久。  
来源：[compose/README.md · What runs where](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/compose/README.md)

## 3. 精确安装命令（Compose）

官方两文件安装（**无其它依赖文件**）：

```bash
mkdir e2b && cd e2b
curl -fsSL --remote-name-all "https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/compose/{compose.yaml,.env}"
docker compose up -d --wait
```

来源：[introducing-e2b-embed](https://e2b.dev/resources/introducing-e2b-embed)、[compose/README.md · Install](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/compose/README.md)

首次 `up` 会：检查并准备主机 → 下载 Firecracker 产物（约 60 MB）→ pull 固定镜像 → 迁移/种子库 → 构建 `base` template。成功条件是 **base template ready**（约 2 分钟于 8 vCPU / 32 GiB VM；更小主机更久）。失败不回滚，步骤幂等，按 `FIX:` 修完再 `up` 即可。  
来源：同上

可选：把安装钉在某 commit（把 URL 里的 `main` 换成 commit SHA）。  
来源：[REFERENCE.md · Images and pins](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/docs/REFERENCE.md)

### 卸载顺序

```bash
docker compose down              # 停栈；sandbox 结束；数据与主机状态保留
docker compose down -v           # 连同数据库与 team key；下次 up 会重建 base
docker compose --profile purge run --rm host-teardown   # 撤销 host-setup（须先 down -v）
```

来源：[compose/README.md · Remove](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/compose/README.md)

## 4. 起来之后：API key / SDK URL / Dashboard

### 取凭证（推荐）

```bash
eval "$(docker compose exec ready cat /run/e2b/sdk.env)"
# 或：docker compose logs ready
```

`ready` 写出的环境变量（compose 内逻辑）：

- `E2B_API_KEY` — 本安装生成的 team API key  
- `E2B_API_URL=http://localhost:3000`  
- `E2B_SANDBOX_URL=http://localhost:3002`  
- `E2B_DASHBOARD_URL=http://localhost:3001`

浏览器打开 `$E2B_DASHBOARD_URL`，把 `$E2B_API_KEY` 贴进 key 表单。  
来源：[compose/README.md · Try it](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/compose/README.md)、[introducing-e2b-embed](https://e2b.dev/resources/introducing-e2b-embed)（亦写 `docker compose logs ready`）

### SDK 冒烟（官方钉的版本）

```bash
python3 -m venv .venv && .venv/bin/pip install e2b==2.46.0
```

```python
from e2b import Sandbox
sbx = Sandbox.create("base")
print(sbx.commands.run("echo hello from the sandbox").stdout)
sbx.kill()
```

或容器内 smoke：`docker compose --profile test run --rm smoke`。  
来源：[compose/README.md · Try it](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/compose/README.md)

### 访问 sandbox 内端口

Embed **没有** Cloud 的 `https://{port}-{id}.e2b.app` 解析。经 client-proxy **header 路由**：

```bash
curl -H "E2b-Sandbox-Id: $SANDBOX_ID" -H "E2b-Sandbox-Port: 8080" http://localhost:3002/
```

来源：[REFERENCE.md · Reaching a port inside a sandbox](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/docs/REFERENCE.md)

### 远程浏览器

本机或 SSH 隧道下，默认 `localhost` 即可。若从**另一台机器无隧道**打开 Dashboard，需在 `.env` 设 `E2B_DASHBOARD_HOST=<本机可被浏览器访问的地址>` 再 `up`（只重建 dashboard）。  
来源：[compose/README.md](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/compose/README.md)

## 5. 网络要点

### 协议与边界

- Embed 在网内提供 **纯 HTTP**，自带 **无 TLS**；应放在可信网络内。  
  来源：[embed/README.md · Limitations](https://github.com/e2b-dev/runtime/blob/main/embed/README.md)、[introducing-e2b-embed](https://e2b.dev/resources/introducing-e2b-embed)

### 主机网络上的 13 个端口（`*:` 监听）

摘自 [REFERENCE.md · Ports on the host network](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/docs/REFERENCE.md)：

| 端口 | 服务 | 谁该能连 | 用途 |
|---|---|---|---|
| **3000** | api | 可信客户端 | SDK 调用的 REST API |
| **3001** | dashboard | 可信客户端 | Web Dashboard |
| **3002** | client-proxy | 可信客户端 | sandbox 流量（header 路由） |
| 3003 | client-proxy | 仅本机 | health |
| 3010 | dashboard-api | 仅本机 | Dashboard 后端 |
| 5007 | orchestrator | 仅本机 | 经 3002 进 sandbox 的代理 |
| **5008** | orchestrator | **仅本机** | **无认证** gRPC 控制面（创建/杀 sandbox、开 template build） |
| 5009 | api | 仅本机 | 内部 gRPC |
| 5010 / 5016 / 5017 / 5018 | orchestrator | 仅本机 | sandbox 出站代理（无对外认证） |
| 5109 | api | 仅本机 | edge gRPC |

官方硬性建议：必要时只对可信客户端暴露 **3000 / 3001 / 3002**；**其余 10 个端口在主机持有的每个地址上（含公网地址）都不可达**。**5008 优先级最高**——谁连上谁就等于掌控整个 orchestrator。  
来源：[REFERENCE.md](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/docs/REFERENCE.md)、[compose/README.md · Known limitations](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/compose/README.md)

### 环回端口（`127.0.0.1:`）

| 端口 | 用途 |
|---|---|
| 5432 | Postgres |
| 6379 | Redis |
| 8123 / 9000 | ClickHouse |
| 30006 | Vector 日志接收 |
| 44313 | Vector API |
| 6060 / 6061 | api / orchestrator pprof |
| 4317 / 13133 | 可选内置 OTel collector（`COMPOSE_PROFILES=otel`） |

来源：[REFERENCE.md · Ports on loopback](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/docs/REFERENCE.md)、[compose.yaml](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/compose/compose.yaml)

### 推荐隧道（不要裸开）

```bash
ssh -N -L 3000:127.0.0.1:3000 -L 3001:127.0.0.1:3001 -L 3002:127.0.0.1:3002 -L 5008:127.0.0.1:5008 <user>@<host>
```

带 `copy()` 的 template build 会经 5008 上传；隧道后栈下发的 `http://127.0.0.1:5008/...` 才有效。  
来源：[compose/README.md · Ports](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/compose/README.md)

## 6. Embed **不包含**什么

产品公告原文：

> E2B Embed does not include **secrets**, **volumes**, **workload identity** or **bring-your-own proxy**.

来源：[introducing-e2b-embed](https://e2b.dev/resources/introducing-e2b-embed)

其它相关边界（同一套一手资料）：

- **无内置 TLS / 域名路由**（Cloud 式 `*.e2b.app` 在 Embed 上不解析）——见 [embed/README.md](https://github.com/e2b-dev/runtime/blob/main/embed/README.md)、[REFERENCE.md](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/docs/REFERENCE.md)
- **无身份提供商**（OIDC 警告为预期噪音）；网络对等体除 api 的 API key / admin token 外**无其它认证**——见 [compose/README.md · Known limitations](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/compose/README.md)
- **单机**：orchestrator 重启即结束其上运行中的 sandbox，无处 drain——见 compose README / REFERENCE
- 默认**不**导出 OTel；需设 `E2B_OTEL_COLLECTOR_GRPC_ENDPOINT`（及可选 `COMPOSE_PROFILES=otel`）——见 [.env](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/compose/.env)、[REFERENCE.md · Observability](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/docs/REFERENCE.md)

## 8. 与已有 Langfuse Docker 共址的风险（家庭实验室）

前提：官方写的是 **dedicated host**，且 **每主机只能一套、无端口改名旋钮**。下列冲突来自两边 compose 的默认绑定对照（E2B：[compose.yaml](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/compose/compose.yaml) + [REFERENCE.md](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/docs/REFERENCE.md)；Langfuse：[docker-compose.yml](https://github.com/langfuse/langfuse/blob/main/docker-compose.yml)、[端口说明](https://langfuse.com/self-hosting/deployment/docker-compose)）。

### 8.1 端口冲突（高）

| 端口 | E2B Embed | Langfuse 默认 | 风险 |
|---|---|---|---|
| **3000** | api（**host network**，绑所有接口） | `langfuse-web` 映射 `3000:3000` | **必撞**。Embed 无法在 `.env` 改 API 端口（无旋钮）；只能改 Langfuse 主机侧端口（如 `3001:3000`）并改 `NEXTAUTH_URL`——但又会与 Embed dashboard **3001** 冲突 |
| **3001** | dashboard（host network） | （若把 Langfuse 挪到 3001） | 与 dashboard 撞 |
| **5432** | Postgres → `127.0.0.1:5432` | Postgres 常绑 `127.0.0.1:5432` | **环回撞**；`up` 时一边起不来 |
| **6379** | Redis → `127.0.0.1:6379` | Redis 常绑 `127.0.0.1:6379` | 同上 |
| **8123 / 9000** | ClickHouse → `127.0.0.1` | Langfuse ClickHouse 同样常用这两端口 | 同上 |
| 3030 | （E2B 不用） | Langfuse worker `127.0.0.1:3030` | 通常无冲突 |
| 9090 | （E2B 不用） | MinIO | 通常无冲突 |
| 4317 | 可选 OTel | 若本机另有 collector | 仅在开 `otel` profile 时可能撞 |

**推断建议**：不要指望「改几个 `.env`」把 Embed 塞进 Langfuse 同机同网栈；要么 **独立 VM/物理机**，要么接受改 Langfuse（及本机其它服务）端口并仔细防火墙，且仍无法改 Embed 的 host-network 服务端口集合。

### 8.2 Hugepages / 内存（高）

- 默认 `HUGEPAGES=2048` → **约 4 GiB** 从主机可用内存划给 Firecracker guest。  
- 推荐整机 **12 GiB+**；与 Langfuse（自身还跑 Postgres / Redis / ClickHouse / MinIO / worker）叠在一起，家庭实验室常见 16–32 GiB 机器会很快吃紧。  
- 可在 `.env` 降低 `HUGEPAGES` / `PF_MIN_FREE_GIB`，但会直接压低并发 sandbox 容量（默认池大约撑满内存时 ~8 个 512 MiB base，或约 20 个空闲）。  
  来源：[compose/README.md · Requirements](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/compose/README.md)

### 8.3 Firecracker / 内核突变（高）

- 需要真实 **KVM**；嵌套虚拟化未开则 `preflight` 失败。  
- 加载 **nbd**（默认最多 64 设备 → 并发 sandbox 上限相关）、改 sysctl、写 udev/modprobe、加 iptables MSS 规则、在根盘建 `/var/lib/e2b` 与 `/fc-*`。  
- orchestrator 以 **privileged + `network_mode: host` + `pid: host` + `cgroup: host`** 经 `nsenter` 跑在主机命名空间——对「已在跑生产可观测栈」的共享主机是侵入式变更。  
  来源：[compose.yaml](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/compose/compose.yaml)、[compose/README.md](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/compose/README.md)、[REFERENCE.md](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/docs/REFERENCE.md)

### 8.4 安全面（中–高）

- 13 个端口绑 **所有接口**；其中 **5008 无认证**。家庭实验室若主机有公网 IP / 宽防火墙，风险极大。  
- Dashboard cookie **非 Secure**（明文 HTTP）。  
  来源：[compose/README.md · Known limitations](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/compose/README.md)、[REFERENCE.md · Secrets](https://raw.githubusercontent.com/e2b-dev/runtime/main/embed/docs/REFERENCE.md)

### 8.5 共址结论

| 选项 | 说明 |
|---|---|
| **推荐** | 另开一台（或嵌套虚拟化 VM）专跑 Embed；Langfuse 保持原机 |
| 强行共址 | 先解决 **3000 / 5432 / 6379 / 8123 / 9000**；确认 KVM；下调 `HUGEPAGES`；防火墙锁死除 3000–3002 外的 Embed 端口；接受 host-setup 改内核参数与模块 |
| 不推荐 | 在已承载 Langfuse 的同一 Docker 主机上「试一下 up」而不先盘点端口与 hugepages——极易半改主机状态（官方：失败步骤幂等但不自动回滚） |
