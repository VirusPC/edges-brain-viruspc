Part A · 目标

这一课你要带走什么

读完并按清单自行操作后，你应能：

  • 用完整中文解释：dsh 是一套可插拔的 agent harness（智能体运行时框架），不是某一个大模型，也不是「换皮版 Claude Code」。
  • 说明 dsh web 选中的是名为 web 的 profile（配置档 / 组装），随后才在浏览器里配置模型。
  • 从空目录走通：启动 → 打开带启动令牌（token）的 URL →（可选）填密钥 → 小文件任务 → 自己核对产物 → 正确退出。
  • 遇到 EADDRINUSE …:3080 时，知道这是 webserver 绑定失败，其它插件「等待服务」往往是连锁结果，并会用 lsof / 换端口处理（不盲目 pkill）。
证据标签（贯穿本课） 观察事实本会话在你 Mac 上测到的现象； 源码结论官方文档或标签源码； 迁移建议给你自己基于 Pi 的 agent 的提示； 未证实聊天里说过但本课不采信的说法。

Part B · 全貌

dsh 是什么

源码结论 官方 README写明： DeepSeek Harness（命令名 dsh）是 DeepSeek AI 开发的开源 agent harness。 它构建于「一切皆插件」架构，由 Cordis（一套把服务、事件、可逆副作用组织成插件树的框架）驱动。 当前处于开发者预览：会有破坏兼容性的变更；运行前应阅读 SAFETY.zh.md。

三个容易混在一起的东西

大模型（LLM）
例如 DeepSeek 的聊天模型本身：负责推理与生成。它不知道你仓库里有什么文件，除非有人把工具与上下文接给它。
客户端 / 界面
你用来看对话、点按钮的外壳：浏览器页面、将来可能的桌面窗、或脚本读到的标准输出。界面不等于「整套能力」。
Harness（本课的主角）
把「模型 + 工具 + 会话日志 + 权限/沙箱 + 多种界面」装配成可运行产品的那一层。dsh 就是这类 harness；换 profile，等于换一套装配。

为什么用起来不像终端里的 Claude Code / Codex

Claude Code、Codex 一类工具，开箱就是固定形态的终端编码助手：一条命令进入交互，产品边界相对封闭。

dsh 的公开入口则强调：唯一受支持的 Node 启动器是 dsh，它启动的是具名 profile——有序的插件组合包（bundle） patch 层，再叠你自己的覆盖。 SDK（软件开发工具包）、ACP（Agent Client Protocol，面向自动化客户端的协议）也都是 profile，而不是另起一套公开二进制。 （见 apps/cli/README.zh.md。）

因此你的第一感觉往往是：「怎么先起了一个网页？」——因为默认推荐的日常入口是 web 这套浏览器 GUI（图形用户界面），而不是内置终端 TUI（文本用户界面）。

观察事实在你本机，dsh tui --help 曾报 profile tui 不存在。 源码结论CLI 文档写 dsh --profile tui … 时，明确加了「assuming the tui profile is installed」。 本课不据此断言「官方有可安装的 TUI 插件包」；只说明：开箱路径请走 web。

一条命令选中的是 profile，不是模型

例如：

  • dsh web 或 dsh --profile web → 启动 $DSH_HOME/profiles/web 这套组装（浏览器 GUI）。
  • dsh --profile headless "……" → 启动 headless 组装，跑完一个任务后退出。

模型提供方、API key、默认模型，是组装启动之后，在 Web 的「设置 → 模型」里配置的另一件事 （或由环境变量 / patch 提供）。把「启动哪套产品形态」和「对话用哪个模型」揉成一个开关，是另一类产品的习惯；dsh 刻意拆开。

一个 profile 里到底有什么

源码结论按架构文档与 CLI README，一个 profile 目录大致包含：

  • package.json：其中的 dsh.profile.bundles 列出有序组合包；也可声明树外插件依赖。
  • cordis.patch.yml：你（或设置页）对该 profile 的覆盖层。
  • 安装后的 node_modules：树外插件落在这里。

配置树从空根叠起：各 bundle 的 patch → profile 的 cordis.patch.yml → home 级 $DSH_HOME/cordis.patch.yml → 命令行 --patch。 默认 Harness home：显式配置 → 环境变量 $DSH_HOME → ~/.dsh （包 dsh-home-paths）。

未证实（已纠正）「主配置就是 ~/.dsh/settings.yaml」——过时。 模型页写入 profiles/<name>/cordis.patch.yml；密钥在 $DSH_HOME/.credentials.yaml。 若仍有旧版 settings.yaml，Settings 插件会导入一次并改名为 settings.yaml.imported。

五类随附 profile：给谁用、典型场景

源码结论发行版随附模板：web、headless、sdk、sdk-minimal、acp。 名称 desktop 保留给 Electron 桌面壳，npm CLI 拒绝替你启动它。 （架构文档 / CLI README。）

web — 浏览器里的日常编码助手

给谁：人坐在电脑前，想点选工作区、看对话、改设置、偶尔审批工具调用。

典型场景：dsh web 后打开打印的 URL，在空练习目录里改文件、跑命令。

非场景：CI 流水线里无人值守跑一条任务（更适合 headless）；给外部程序用 JSON-RPC 驱动（更适合 sdk）。

组合上通常是共享的 dsh-base + dsh-web-app（浏览器应用层）。

headless — 一次性任务，跑完就退

给谁：脚本、CI、只想在终端拿最终答案的人。

典型场景：dsh --profile headless "run the tests"；可 --json 输出事件流。

非场景：需要长时间盯着 GUI 多轮点选时——官方建议改用 web。

注意（避免过度绝对化）：headless「主要边界」是每次调用跑一个任务、没有交互式后续； 但监督进程仍可用 --session-id 在同一段已持久化对话上继续唤醒，并用 --json 读进度。 它默认不开监听端口、任务结束后进程退出；这不等于「完全不能做任何会话控制」。

凭据方面：随附 headless 默认禁用托管凭据存储，更依赖环境 / .env；与 web 的「设置页存 key」习惯不同。

sdk — 给程序用的完整 JSON-RPC 服务

给谁：要用 TypeScript / Python SDK 把 dsh 嵌进自己工具链的开发者。

典型场景：dsh --profile sdk，客户端经标准输入输出上的 JSON-RPC 驱动，直到关闭。

非场景：只想本机开网页聊两句（用 web 即可）。

它建立在共享 dsh-base 之上，因此带上完整产品基础（设置、凭据、更完整工具清单等——以 base 为准）。

sdk-minimal — 刻意变瘦的 SDK 组合

源码结论 sdk-minimal README： 这是独立组合包，提供完整显式 Cordis 配置树，并排除 dsh-base、Web、settings、托管凭据、遥测、文本文件工具、workspace 指令、skill、jobs 与 subagent。 默认工具侧重持久 shell、read_image、working_directory；danger-full-access 策略下 shell 可改进程能访问的路径，必须配合隔离 workspace。

给谁：需要小型、边界清晰的跨平台 coding agent 运行时，且能接受「少很多产品功能」的 SDK 调用方。

非场景：你还想要 settings UI、托管凭据、完整默认工具——请改用 sdk。

acp — Agent Client Protocol 自动化通道

给谁：通过 ACP 标准输入输出对接的自动化客户端。

典型场景：dsh --profile acp，服务直到断开。

非场景：人类日常点选编码（用 web）。

进阶：组合包名字速查（本课不必背）

安装目录会解析诸如 @deepseek-ai/dsh-base、@deepseek-ai/dsh-web-app、@deepseek-ai/dsh-headless、 @deepseek-ai/dsh-sdk-app、@deepseek-ai/dsh-sdk-minimal、@deepseek-ai/dsh-acp-app。 之后的「profile 装配」课再拆 patch 如何按 id 替换整段 config。

心智图：从 web 连到插件装配、Cordis 与 pi-ai

第一课只搭骨架，不灌实现细节。请先建立这张图：

你输入:  dsh web
            │  ① 启动器只解析「要哪个 profile」
            ▼
   ~/.dsh/profiles/web/     （或 $DSH_HOME/...）
   · bundles 有序列表
   · cordis.patch.yml
            │  ② Cordis Loader 按层挂载插件
            ▼
   ┌─────────────────────────────────────┐
   │  dsh-base（模型适配、工具、会话、沙箱…） │
   │  + dsh-web-app（浏览器 GUI / 端口）     │
   │  + 你的 patch / 设置页写入               │
   └─────────────────────────────────────┘
            │
            ├─③→ 浏览器 UI @ 127.0.0.1:3080
            │      设置→模型 / 选工作区 / 会话
            │
            └─④→ LLM 适配器之一：dsh-llm-pi-ai
                   （依赖 @earendil-works/pi-ai）
                   把「harness 的生成请求」路由到各提供方
                   另有直连 DeepSeek 的适配器可并存

源码结论 仓内包 @deepseek-ai/dsh-llm-pi-ai 依赖 @earendil-works/pi-ai，用于多提供方 / OpenAI 兼容网关路由。 这与你自己 vendored 的 Pi（pi-agent-core / pi-ai + PiTurnRunner）同属 Pi 生态思路，但包名与边界不同——迁移课再对照，本课只需知道：模型适配也是可替换插件。

迁移建议抄 dsh 时，先问「这是装配层（profile/bundle）还是模型适配层（llm-*）还是界面层（web-app）」；不要把三层捏成一个开关。

Part C · 操作

完整操作路径（请你自己做）

下面用明确示例路径。若你的家目录不同，只替换用户名，保持「专用空目录」原则。

0. 前置

  • 已安装 @deepseek-ai/dsh@0.2.2-rc.1，Node.js ≥ 24.9。终端执行 dsh --version 核对。
  • 本课不代你付费调用；是否填写 DeepSeek API key 由你决定。

1. 准备空练习目录

示例（macOS / zsh 或 bash）

mkdir -p "$HOME/tmp/dsh-sandbox-lesson01"
cd "$HOME/tmp/dsh-sandbox-lesson01"
pwd   # 确认你在空目录里

调用目录会成为默认 workspace 根的参考；但 Web UI 仍要求你在页面里显式选择工作区。空目录用于降低误改真项目的风险——它不是安全沙箱（见下一节）。

2. 前台启动 web

# 仍在 $HOME/tmp/dsh-sandbox-lesson01 中
dsh web
# 或：dsh web --no-open    # 只起服务，不自动开浏览器

默认监听 http://127.0.0.1:3080。终端会打印一行带启动令牌（token）的完整 URL。 不要把真实 token 贴到聊天、截图发群或提交到 git。本课只用占位写法示意：

http://127.0.0.1:3080/?token=<启动时打印的令牌>

源码结论公开部署文档说明：带 token 的入口把令牌换成签名会话 cookie；无令牌的直访会被拒绝。这是预期行为。

前台运行 vs 残留后台：你在当前终端前台跑 dsh web 时，关掉该终端或按 Ctrl+C 应结束该进程。 若曾用另一终端启动、或进程被放到后台、或上次异常退出后仍占用 3080，就会留下「幽灵服务」——下一节专门讲。

3. 打开打印出的 URL

  • 用终端打印的完整链接打开（自动打开失败时手动粘贴）。
  • 若只打开 http://127.0.0.1:3080/ 而无 token，被拒绝是正常的。

4. 选择工作区

在 UI 中选择 / 添加工作区，指向刚才的 $HOME/tmp/dsh-sandbox-lesson01。未选中前，会话输入框不可用（Web UI 指南）。

5. （可选）配置模型——不把 key 发给任何人

打开设置 → 模型，在 DeepSeek 卡片自行粘贴 API key 并保存。 密钥只写存储；页面之后只看到脱敏描述。也可在启动前自行 export DEEPSEEK_API_KEY=…（勿写入本课程文件）。

若本课你只想验证「装配能起来」，看到 UI 且能选中工作区即可，不必发真实任务。

6. 安全的小文件任务（可选，会产生模型费用）

建议提示词

请在当前工作区创建一个文件 hello-dsh.txt，文件内容只有一行：dsh-web-ok。不要修改其它路径。

预期产物

工作区出现文件 $HOME/tmp/dsh-sandbox-lesson01/hello-dsh.txt，内容为 dsh-web-ok（允许末尾换行）。

你自己检查（不要只听 agent 口头说「写好了」）

cd "$HOME/tmp/dsh-sandbox-lesson01"
ls -la hello-dsh.txt
cat hello-dsh.txt

若 UI 弹出审批，先读命令与路径再允许。

7. 退出与再启动

  • 在跑着 dsh web 的终端按 Ctrl+C，等待进程退出。
  • 再启动时重新执行 dsh web；新的启动令牌会出现在新的打印 URL 里——旧 token 不要复用。
  • 会话数据在 Harness home 下持久化；练习目录里的 hello-dsh.txt 是你的工作区文件，删不删由你决定。

权限、费用与「空目录 ≠ 沙箱」

请认真对待
  • 文件与命令：agent 可能读写工作区、跑 shell。错误输出、错误批准或恶意插件都可能改文件、泄凭据。官方 SAFETY：沙箱与审批可降低风险，但不保证隔离。
  • 空目录只是习惯防护：它降低你「一上手就指到家目录 / 真仓库」的概率，但不是虚拟机级沙箱。工具一旦拿到更宽权限，仍可能影响其它路径。
  • 模型费用：每次真实对话与工具循环都可能计费。本课的小任务故意极短；不需要时不要反复重试。
  • 令牌与 URL：打印的启动 URL 含进程凭据，只给你自己用。

真实案例：3080 被占用时的连锁失败

观察事实（来自你本机排障经验，已抽象成模式）：当 127.0.0.1:3080 已被占用时，webserver 会以类似 EADDRINUSE 的错误启动失败。 日志里还可能出现其它插件「等待某服务」的警告——这通常是因为 required / 依赖的 web 服务没起来，属于同一故障的连锁结果，不要当成两个互不相关的独立 bug 分别「乱修」。

在 Mac 上先看清是谁占用了端口

lsof -nP -iTCP:3080 -sTCP:LISTEN
# 记下 COMMAND / PID / 用户
ps -p <上面看到的PID> -o pid,ppid,user,start,command

用 ps 确认那是不是你之前没关掉的 dsh / node。只有确认是自己的残留进程时，才在该终端用你平时结束前台任务的方式结束它，或针对已辨认的 PID做一次有意识的终止。 不要教也不会建议无差别的 pkill node / 乱杀进程——可能误伤其它项目。

说明：此前一次排障中，残留进程曾占用 3080，主助手在确认身份后已结束该进程并核对端口释放。本课不要求你对任何历史 PID 再执行一次杀死；只把「先辨认、再处理」当作教训。

或者：换端口启动

源码结论web-app 文档示例支持 --port，例如 dsh --profile web --no-open --port 8080。 观察事实本机 dsh web --help 亦展示端口相关选项；可用：

dsh web --port 3081
# 或让系统分配空闲端口（help 支持 --port 0 时）：
dsh web --port 0

换端口后，务必打开新打印的带 token URL（主机仍是 127.0.0.1，端口以打印为准）。
