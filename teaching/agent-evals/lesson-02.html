三类 grader：能确定性就别全靠模型

grader 给 trial 打分。同一 task 可组合多种：能用代码验的先用代码；模型评分要靠人校准；人是金标准，但贵且慢。

主文献：Anthropic · Demystifying evals for AI agents · 2026-01-09

← 第 1 课 术语速查 原文

这一课你要带走什么

能说出三种 grader 各自擅长什么，并在订票 / 改文件场景里选默认优先用哪一种——尤其记住：能确定性检查时，不要一上来就全交给 LLM judge。

grader 是什么

grader：对 agent 表现某一侧面打分的逻辑。一个 task 可以有多个 grader；每个 grader 里又可有多条 assertion（checks）。它们可以评 transcript（过程），也可以评 outcome（环境终态）。

计分常见三种拼法：全部通过（binary）、加权达阈值（weighted）、或混合（hybrid）。

三类 grader

code-based 代码 / 确定性
字符串匹配、单元测试、静态分析、状态检查、工具调用校验、token/轮数统计。快、便宜、可复现；但对合法变体可能过脆，难评主观质量。
model-based 模型评分
按 rubric / 自然语言断言 / 成对比较 / 参考答案 / 多 judge 共识。灵活、可扩展；非确定性、更贵，必须与人类校准。
human 人工
专家评审、抽检、众包、一致性检查。金标准，并用来校准 model grader；贵、慢，难大规模常开。
原文取向 能确定性就用确定性；需要灵活或开放输出时用模型评分；人工用于校验与校准——而不是默认让 LLM 包办一切。

例子 A：订票

同一 task，不同 grader

  1. code-based：查库——refunds 是否 processed、tickets 是否 resolved；是否调用了 verify_identity / process_refund；轮数是否 ≤ 10。
  2. model-based：rubric 评「是否共情」「解释是否清楚」「答复是否 grounded 在政策工具结果」。
  3. human：抽检难例，核对 LLM rubric 是否与客服主管一致；分歧就改 rubric。

库里没退款成功，却被模型夸「态度很好」——code-based outcome 检查仍应判失败。

例子 B：改文件

修空密码登录漏洞

  1. code-based：指定失败测试转绿、既有测试不挂；可选 ruff / mypy / 安全扫描；核对安全日志事件。
  2. model-based：rubric 评代码清晰度、是否过度工程、工具使用是否合理。
  3. human：定期抽样，确认「质量」rubric 没漂；别让模型自己给自己发满分。

实践上 coding 常以单元测试 + 必要的 LLM rubric为主，其余按需加——不必一次堆满所有 grader。

选型口诀

  • 终态能查库 / 跑测 → 先 code-based。
  • 语气、共情、开放综合 → model-based，并做人机对齐。
  • 定金标准、校准、抽查争议 → human。
  • 少绑死「必须按某顺序点工具」——合法路径不该被脆检查误杀。
