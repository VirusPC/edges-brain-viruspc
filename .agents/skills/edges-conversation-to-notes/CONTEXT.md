# CONTEXT — edges-conversation-to-notes

## Glossary

- **复盘笔记**：由一场（或多场）对话整理出的、可独立阅读的中文笔记；本 skill **同时做记录与复盘总结**。入库用户选定 scope 或 Project 的 Notes，不默认写入 Edges 框架仓。
- **背景**：为何开这场、意图；不是过程流水。
- **主题**：正文大章。先一段话点明这场在学/谈/办什么，其下用列表写**难点**。章节标题不加括号。
- **难点**：主题章下列出的难处（技术或非技术均可）：难在哪、卡在哪。主要落在「主题」，所学可展开。
- **过程时间线**：过程章节按时间推进；小节标题带具体时刻或时间段；少评价。过程中的真实取舍原样保留，不压缩删减。
- **结果**：过程之后的大章。写成了什么、还剩什么、有无回退；少讲原理。
- **所学**：复盘向的理解与边界；在此**补充**取舍（可选项与为何不做、最终知识与方案），不是把过程折短。
- **主题行动指南**：行动指南中的主题层。包含：背景、核心问题、核心解决方案（可执行步骤）、验收标准。只写角色与机制，不绑具体主机名、网段、脚本路径。写做法时默认带可选项与不做原因；无比较空间时可省略。
- **细节与其他**：行动指南中的细则层。每条一个 Markdown 小标题，形如「若…」；正文写「则…」；复杂步骤用列表。主机名、路径、网段、账号等操作细节只出现在这一层。写法则时默认同样带可选项与不做原因；无比较空间时可省略。
- **验收标准**：主题行动指南的最后一节。当作以后「当真把这件事当任务执行」时的完成判定清单（可勾选），不是散文式愿望。
- **取舍补充**：在所学与行动指南中追加的可选项与弃因；与过程中的真实 tradeoff 并存，不互相替换。
- **白话**：完整中文句；禁止自创黑话、口头禅式小标题、未经解释的自创缩写。真实产品/协议名可保留。
- **行动类对话**：讨论本身以「要做成某事」为主；整理时内容优先进入行动指南，所学仍可补充取舍。
- **学习类对话**：讨论以理解知识点为主；所学写知识点总结，行动指南单独写「如何用」。
- **总览笔记**：同日或多主题的一篇主线笔记，链到各主题 note；补充说明可引用其它 note。
- **原始材料引用**：笔记必须留下可追溯出处（会话/助手、PR/commit、本地路径、相关 note 等）；整理不等于丢原料指针。
- **路径名 / 显示标题**：所选材料根下的路径用 `notes/YYYY-MM-DD--主题简述/INDEX.md`；默认材料根为 scope/.edges，Project 为 P，未选 Project 的 super 为 scope。`--title`、`#`、frontmatter `title` 只写主题简述。
- **遗留项转任务**：笔记「结果」里尚未闭环的事项；整理后默认逐点问清（背景/目标），再交 `edges-conversation-to-tasks` 开卡，一次 1～2 条。
