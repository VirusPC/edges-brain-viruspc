# 把笔记或知识条目做成对外成稿

把已有笔记、知识条目（尤其是从语雀导出来的长文）迁到站点的对外成稿目录，或修复这类成稿在发布页上的渲染问题。

## 先读规则，不要默认写入

成稿目录（常见是 `posts/`）往往由人仔细维护，仓库的 `AGENTS.md` 或该目录的说明里可能禁止助手自动新建、移动或改写。即使用户说「改成文章」，也先读这些规则。不要改掉这条规则本身。

- 规则禁止写入：先停手，说明原因，问用户是否破例开合并请求直接写入，还是只在该目录以外起草、再由用户自己贴入。
- 用户明确授权破例：可以开合并请求写入，并在说明里写明这是当次授权。

## 定位和站点约定

1. 按标题或关键词找到原文，可能不只在 `notes/`，也要看知识条目目录（例如 `edges/`）。多篇近似时先请用户选定，不要猜。
2. 读几篇已有成稿，以及站点如何收录该目录：常见是收录除说明文件外的 Markdown；可选文首信息为标题、日期、简介、草稿标记；没有文首信息时，标题取文首标题，日期取文件名前缀。确认站点支持「日期前缀目录 + 入口文件 + 配图子目录」，还是只要单文件。
3. 问清：原件是迁走还是复制保留。没有交代就先问一句。

## 迁移

- 用独立的 git 工作副本和分支，优先 `git mv` 保留历史。
- 配图随文搬进对应目录，保持相对路径仍能打开。
- 按站点约定补文首信息：标题、日期（优先用原文里的更新日期）、一句简介。正文意思不要改写。
- 原文若有索引或交叉链接，一并改掉。
- 磁盘紧张时不要做完整检出的工作副本，只检出要用的路径。

## 发布前检查语雀导出的常见问题

用站点同一类 Markdown 规则检查，不必为此安装大型依赖。重点看：

- **未闭合的围栏**：单独一行的四个波浪号，或三个反引号，会被当成代码块开头；后面又没有收尾时，从这一行到文末都会变成直接显示原文。删掉多余的围栏即可。
- **标题层级**：语雀导出常把大节写成一级标题，和文章题目同级、也一样大。侧栏目录若默认只收二级标题，这些大节进不去，看起来就像没有多级。把标题整体往下挪一级（只留文题为一级），大节变二级，小节变三级，以此类推。不要改正文。
- **目录混进图片**：把图片写成了标题（标题标记后面直接跟图片语法），或文首那份导出目录里列了图片项。改回普通配图，并从目录里拿掉。侧栏往往会跳过没有文字的标题，所以问题有时只出现在文首那份目录里。
- **残留标记**：导出留下的颜色标签、半开的加粗符号等，发现了就问要不要顺手清，不要默默大改。

顺手检查同一批迁过去的其他成稿，避免只修一篇、另一篇还是旧问题。

## 侧栏目录深度

用户希望目录显示到三级时，只改成稿页自己的 `tocDepth`，不要把组件默认改成三级，以免笔记、项目、教学等页面一起变。四级及以下默认不进目录。若组件已有嵌套缩进，就不要另改样式。

## 提交

按该仓库的约定提交（作者、中文说明、合作署名），开合并请求，不要自行合并，除非用户明确说合并。
